# ユーザーガイド

<br/>

<a id="introduction"></a>
## 導入

Transrewrt は、テキストを以下の3つの方法で処理するのを支援します。

- **翻訳** - テキストをある言語から別の言語に変換します。
- **リライト** - より明確、短く、またはよりフォーマルなスタイルなど、異なるスタイルでテキストを言い換えます。
- **変換** - プロンプトと呼ばれるカスタムAI指示を使用してテキストを処理します。

<br/>

このガイドでは、アプリのインストールと実行後の使い方を説明します。インストール手順については、メインの **[README](README.ja.md)** をご確認ください。

<br/>

> ℹ️ **注記**<br/>
> Transrewrt は、WindowsおよびLinux向けのデスクトップアプリとして、またセルフホスト型のWebアプリとして利用可能です。このガイドではアプリの日常的な使用方法を中心に説明しています。特定のバージョンにのみ適用される内容については、明確にマークしています。

<a id="before-you-start"></a>
## はじめに

Transrewrt を使用するには、少なくとも 1 つの AI プロバイダーへのアクセスが必要です。サポートされているプロバイダーは以下のとおりです：[OpenRouter](https://openrouter.ai)（多数のモデルを統合）、OpenAI、Anthropic、Google Gemini、DeepSeek、Groq、Mistral、xAI、Cerebras、およびローカルモデル用の[Ollama](https://ollama.com)。

開始する際に有料モデルを選択する必要はありません。OpenRouter の API キーを追加すると、アプリは自動的に組み込みの**無料**OpenRouter オプションを有効にします。これにより、すぐにテキストの翻訳、リライト、変換を開始できます。また、Cerebras、Google、Groq、または Mistral AI から無料の API キーを取得することもできます。

わかりやすく言うと：

- **モデル**とは、処理を行う AI エンジンのことです。モデルは**プロバイダー接頭辞**（例：`openrouter/…`、`openai/…`、`ollama/…`）付きで表示されます。
- **API キー**（または Ollama の場合は**ベース URL**）は、アプリがそのプロバイダーに接続するための手段です。

**デスクトップアプリ**を使用している場合は、使用する各プロバイダーに対して[**設定** > **API設定**](#api-config)でキーを追加します。OpenRouter 専用の場合は、下記の「[API キーの取得方法](#how-to-get-an-api-key-desktop-app)」を参照してください。API キーを使用したくない場合は、[ollama.com](https://ollama.com) から Ollama をインストールし、`translategemma:4b` などのローカルモデルを使用できます。

**Web バージョン**を使用している場合、サーバーの管理者が環境変数でプロバイダーを設定するため、アプリ内に直接 API キーを入力することはできません。

<br/>

<a id="how-to-get-an-api-key-desktop-app"></a>
### 無料の OpenRouter API キーを取得する方法（デスクトップアプリ）

デスクトップアプリを使用している場合は、以下の手順に従ってください：

1. Web ブラウザで[OpenRouter](https://openrouter.ai) にアクセスします。
2. アカウントを作成またはログインします。
3. [Keys](https://openrouter.ai/keys) ページを開きます。
4. 新しい API キーを作成するボタンをクリックします。
5. 後で識別できるように、キーに名前を付けます。
6. 新しい API キーをコピーします。
7. Transrewrt に戻り、**設定** > **API設定** を開きます。
8. **OpenRouter API キー**（**設定** > **API設定**内）にキーを貼り付けます。
9. **OpenRouter キーをテスト**をクリックして、正しく動作するか確認します。

<br/><br/>

<a id="getting-started"></a>
## はじめましょう

Transrewrt を初めて使用する場合は、以下の順序で進めてください：

1. アプリを開きます。
2. 必要に応じて、地球儀アイコンから**インターフェース言語**を選択します。
3. **デスクトップアプリ**を使用している場合は、[**設定** > **API設定**](#api-config)を開き、少なくとも 1 つのプロバイダー（例：OpenRouter）の API キーを追加し、**テスト**をクリックして正しく動作するか確認します。
4. [**設定** > **モデル**](#models)を開き、**選択済みモデル**に 1 つ以上のモデルを追加します。
5. [**設定** > **言語**](#languages)を開き、頻繁に使用する言語を上位に表示させたい場合は、**トップ言語**を選択します。
6. **翻訳**に移動し、簡単な翻訳を実行して、すべてが正しく動作しているか確認します。
7. それが成功したら、次に**リライト**、その後**変換**を試してみてください。

この順序は重要です。アプリが有効な API 接続を持つことや、モデルが選択されている前にタスクを実行しようとする、最もよくある初回使用時の問題を防ぎます。

### ツールバー

ツールバーは、アプリ内の位置によってわずかに変化します。

- 左側には現在のページ名が表示されます。
- 右側には**モデルセレクター**と**インターフェース言語**のコントロールが表示されます。

<br/>

<a id="input-and-output-panels"></a>
### 入力および出力パネル

ほとんどのワークスペースでは、左側に**入力**パネル、右側に**出力**パネルを使用します。

各パネルには以下も表示されます：

| **入力**                                                          | **出力**                                                                                                                  |
|--------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| - 文字数 <br/>- 単語数 <br/>- 段落数   <br/> | - タスクに要した時間<br/>- **TPS** (1秒あたりのトークン数)<br/>- 文字数、単語数、段落数<br/>- 使用したモデル |

技術用語について疑問がある場合：

- **トークン**とは、テキストの小さな断片を意味します。単語の一部または短い単語と考えてください。
- **TPS**とは、モデルが1秒間に処理したテキストの断片の数を意味します。

<br/>

また、各操作のコスト（利用可能な場合）と合計コストを監視することもできます。[**設定** > **一般設定**](#general-settings)で`アクションにコスト情報を表示`のオプションを有効にしてください。

<a id="translate"></a>
## 翻訳

**翻訳**は、テキストをある言語から別の言語に変換したいときに使用します。

![Translate workspace](../images/screenshots/ja/translate.png)

<br/>

<a id="translate-text"></a>
### テキストの翻訳

1. **翻訳**を開きます。
2. **From**で言語を選択します。
3. **To**で言語を選択します。
4. ツールバーでモデルを選択します。
5. **入力**にテキストを入力または貼り付けます。
6. **翻訳**をクリックします。
7. **出力**で結果を確認します。
8. 結果をコピーする場合は、コピー用のボタンを使用します。

<br/>

<a id="language-selection"></a>
### 言語の選択

- **From**は特定の言語または**言語を検出**のいずれかです。
- **To**は、結果を出力したい言語です。

選択した**トップ言語**は、言語リストの上部に表示されます。これらは[**設定** > **言語**](#languages)で設定できます。

<br/>

<a id="helpful-translation-settings"></a>
### 役立つ翻訳設定

[**設定** > **一般設定**](#general-settings) で、翻訳の動作方法を変更できます：

- **貼り付け時に自動翻訳**：テキストを貼り付けた直後に翻訳を実行します。
- **結果をクリップボードに自動コピー**：実行が成功した後、結果を自動的にクリップボードにコピーします。
- **リアルタイム翻訳（入力中）**：入力中に翻訳を実行します。
- **タイムアウト（ミリ秒）**：リアルタイム翻訳を実行する前にアプリが待機する時間を制御します。
- **Enter**：`Enter` キーを押したときに何が起こるかを制御します：

<a id="rewrite"></a>
## リライト

主な意味を変更せずに言い回しを改善したい場合は、**リライト** を使用します。

![Rewrite workspace](../images/screenshots/ja/rewrite.png)

これは次のような場合に便利です：

- スペルと文法の修正（**スペル＆文法チェック**）
- テキストの明瞭さの向上（**明瞭さを改善**）
- 1回の実行で複数の異なる言い換えを生成（**代替バージョン**）
- テキストをよりフォーマルまたはカジュアルにする（**フォーマル** / **カジュアル**）
- テキストを短くまたは長くする（**短くする** / **展開する**）
- テキストをより専門的にする（**専門的にする**）

<br/>

> 💡 **ヒント**<br/>
> 「**スペル＆文法チェック**」モードを使用すると、出力パネルに「**変更を表示**」スイッチが表示されます（**コピー** の隣）。
> これをオンまたはオフにすることで、テキストに適用された修正内容を表示または非表示にできます。

<a id="transform"></a>
## 変換

カスタムの指示に従ってAIに処理させたい場合は、**変換** を使用します。

![Transform workspace](../images/screenshots/ja/transform.png)

これはアプリの中で最も柔軟性のある領域です。以下のようなタスクに使用できます：

- メモの要約
- ラフなテキストを洗練されたメールに変換
- 主要ポイントの抽出
- テキストを特定の形式に変換
- 入力テキストに対するその他のカスタム処理

<br/>

<a id="run-an-existing-prompt"></a>
### 既存のプロンプトを実行

1. **変換** を開きます。
2. プロンプトリストからプロンプトを選択します。
3. **ターゲット** 言語ボックスが表示された場合は、必要に応じて言語を選択します。
4. **入力** にテキストを入力または貼り付けます。
5. **変換** をクリックします。
6. **出力** で結果を確認します。

<br/>

<a id="if-you-have-no-prompts-yet"></a>
### プロンプトがない場合

プロンプトリストが空の場合は、変換ワークスペースで **サンプルプロンプトを読み込む** をクリックしてください。同じコントロールは [**設定** > **変換プロンプト**](#transform-prompts) のエクスポート/インポート行にも常にあります。どちらも組み込みのサンプルを追加するため、すぐに始められます。

<br/>

> ℹ️ **注意**<br/>
> サンプルプロンプトは英語で提供されています。読み込んだ後、プロンプトを編集し、「**プロンプトを翻訳**」を使用してあなたのレンゲージに翻訳できます。

<br/>

<a id="create-a-prompt-quickly"></a>
### 素早くプロンプトを作成

プロンプトを作成する最も速い方法は次のとおりです：

1. **新規プロンプト** をクリックします。
2. **プロンプトを生成** をクリックします。
3. プロンプトに何をさせたいかを説明します。
4. モデルを選択します。
5. アプリがドラフトを作成するのを待ちます。
6. ドラフトを確認し、**保存** をクリックします。

![Generate prompt](../images/screenshots/ja/transform-generate.png)

<br/>

<a id="edit-a-prompt"></a>
### プロンプトの編集

プロンプトを作成または編集する際、エディタが左側に表示され、右側にテストエリアが表示されます。

![Transform prompt editor](../images/screenshots/ja/transform-prompt-edit.png)

主な項目は以下のとおりです。

- **プロンプト名**: プロンプト一覧に表示される名前。
- **プロンプト指示（任意）**: プロンプト実行時にユーザーに表示される短いヒント。
- **モデルの役割**: AIに割り当てられる全体的なロール。例:「あなたは役立つアシスタントです。」
- **モデル指示（1行に1つ）**: AIに従ってほしい特定のルール。
- **出力の説明**: 結果を表す短い単語。例:「概要」や「リライト」など。
- **温度 (0.0 → 1.0)**: モデルの動作方法。以下を参照。
- **対象言語を確認する**: プロンプト実行時にターゲット言語の選択肢を追加します。

技術用語の **Temperature** が初めての方は、次のように考えてください。

- **低い** Temperature は、安定しており予測しやすい結果をもたらします。
- **高い** Temperature は、より多様で創造的な結果をもたらします。

また、以下の機能も使用できます。

- **`Generate prompt`**: 単純な説明から新しいプロンプトの草案を作成
- **`Improve prompt`**: 既存のプロンプトを洗練
- **`Translate prompt`**: プロンプトの項目を翻訳

<br/>

> ⚠️ **警告**<br/>
> **`Back to Run`** をクリックする前に、必ず **`Save`** をクリックしてください。保存せずに戻った場合、変更内容は失われます。

<a id="general-settings"></a>
### 一般設定

**一般設定**を使用して、入力動作、**履歴**に実行詳細を保存するかどうか、および外観を制御します。

**動作**

- **ENTERの動作**：`Enter`キーでタスクを実行するか、改行を挿入するかを選択します。
- **貼り付け時に自動翻訳**：テキストを貼り付けた直後に翻訳を開始します。
- **結果をクリップボードに自動コピー**：成功した結果を自動的にコピーします。
- **リアルタイム翻訳（入力中）**：入力中に翻訳を行います。
- **タイムアウト（ms）**：リアルタイム翻訳の待ち時間を設定します。

**履歴**

- **実行履歴を保存**：サイドバーの[**履歴**](#history)ビューで、翻訳、リライト、変換ごとに**入力テキストと出力テキスト**を保存するかどうかを制御します。オフにすると確認が求められ、確認するとデータベースから保存された履歴テキストが削除されます。
- **履歴データを削除**：**データを削除**を使用して、期間（たとえば数か月以上前など）または**すべてのデータ（クリア）**に基づいて保存されたテキストを削除できます。これは**履歴**ビューの保存済み実行テキストにのみ影響し、**コスト**または使用量の合計は削除しません。**コスト**データを削除または削減するには、[**設定** > **コスト追跡**](#cost-tracking)を使用します。

**外観**

- **アクションにコスト情報の表示**：利用可能な場合、各操作のコストおよび翻訳、リライト、変換の出力パネルに表示される合計コストの表示を制御します。
- **コスト小数桁数**：コストの小数点以下の表示方法を変更します。
- **Webのみ**：**アプリの周囲に余白を表示**は、インターフェースの周囲に余白を追加します。
- **フォントファミリー**：テキストパネルのフォントを変更します。
- **サイズ**：フォントサイズを変更します。

**設定のバックアップ**

- **バックアップに使用状況データを含める** — 有効にすると、ZIPファイルに実行履歴およびAPI呼び出しデータも含まれます。
- **設定をバックアップ** — `config.json`、`state.json`、任意の暗号化キー、ユーザー、設定、カスタムプロンプト、および使用状況データ（選択した場合）を含む単一のZIPファイル（デフォルトでUTCの`transrewrt-config-backup-YYYY-MM-DD_HHMMSS.zip`）を作成します。バックアップが成功すると、保存されたファイル名が確認メッセージに表示されます。
- **バックアップから復元** — まず**確認ダイアログ**が開きます。ダイアログ内でバックアップZIPを選択（**参照**／ファイルピッカーまたはサポートされている場合はドラッグ＆ドロップ）、次にオプションを確認します：
  - **使用状況データを復元する** — 使用状況を含めてバックアップされた場合、その時点の使用状況／履歴をインポートします。設定とプロンプトのみ必要な場合はオフにしてください。
  - **復元前に古い使用状況データを消去する** — バックアップを適用する前に、このインストールの既存の使用状況／履歴を削除します（任意。完全に置き換えたい場合に使用）。

Web版またはデスクトップ版で作成されたバックアップは、いずれのバージョンでも復元できます。デスクトップ版のバックアップをWeb版で復元する場合、データは管理者ユーザーに復元されます。

<br/>

<a id="models"></a>
### モデル

**設定** > **モデル**を使用して、ツールバーに表示されるモデルを選択します。

![Settings Models tab](../images/screenshots/ja/settings-models.png)

このページには2つのリストがあります：

- 左側の**利用可能なモデル**
- 右側の**選択済みモデル**

便利なコントロールには以下が含まれます：

- **モデルを検索...**：名前でモデルを検索します
- **プロバイダー**チップ：リストを特定のエンジン（OpenRouter、OpenAI、Ollamaなど）に絞り込みます
- **無料のみ**：無料のモデルのみを表示します
- **更新**：リストを再読み込みします
- **すべて展開**および**すべて折りたたむ**：プロバイダー別に並べ替えているときに使用します

モデルIDにはプロバイダープレフィックスが含まれます（例: `openrouter/…` と `openai/…`）。**OpenAI (OpenRouter)** や **OpenAI (direct)** などのバッジは、トラフィックがどのようにルーティングされるかを示しています。

> ℹ️ **注記**<br/>
> **OpenRouter Body Builder** (`openrouter/bodybuilder`) は汎用チャットモデルではなくルーターモデルです。このモデルの応答は、OpenRouter APIリクエストボディ（たとえば、`model` と `messages` を含む `requests` 配列）を記述するJSONになります。このモデルを **翻訳**、**リライト**、または **変換** に使用すると、出力パネルには完成したテキストではなくそのJSONが表示されます。これらのタスクには通常のテキストモデルを選択してください。詳しくはOpenRouterの[Body Builderモデルページ](https://openrouter.ai/openrouter/bodybuilder)をご覧ください。

操作:

- モデルを追加するには、**追加** をクリックするか、エントリの任意の場所をクリックします。

- モデルを削除するには、**選択済みモデル** で隣の **X** をクリックするか、利用可能なモデルのエントリにある **選択済み** をクリックします。

- リストをクリアするには、**すべて選択解除** をクリックします。必須の無料モデルはリストに残ります。

<br/>

> ℹ️ **注記**<br/>
> OpenRouterにすぐにクレジットを追加したくない場合は、まず **無料のみ** を有効にして無料モデルを選択してください（クレジットカード不要）。また、Ollamaを使用してAPIキーなしでローカルでモデルを実行することもできます。

<br/>

<a id="cost-tracking"></a>
### コスト追跡

**設定** > **コスト追跡** を使用して、コスト情報の管理を行います。

- **合計コスト** は累計を表示します。
- **値をコピー** は合計をクリップボードにコピーします。
- **コストをリセット** は保存された合計をゼロにリセットします。
- **APIキー使用量と同期** は、合計をOpenRouterアカウントで報告された使用量に合わせます（OpenRouterのみ）。
- **APIキー使用状況** は、利用可能な場合にOpenRouterの使用詳細を表示します。
- **コストデータを削除** はすべてのデータを削除するか、選択した日付より前のエントリのみを削除します。

**コスト追跡:** OpenRouterモデルを使用すると、アプリはOpenRouterから提供されるコスト情報に基づいて、実際の使用量と支出を表示します。その他のすべてのプロバイダーについては、アプリはOpenRouterが公開している価格を使用してコストを推定します。価格が利用できない場合、推定値はゼロになることがあります。

<br/>

> ℹ️ **注記**<br/>
> すべてのコスト数値は参考用の推定値であり、公式な請求書ではありません。

<br/>

> ⚠️ **警告**<br/>
> データの削除は元に戻せません。削除する前に、[**履歴**](#history) または [**ダッシュボード** > **全コール**](#dashboard-tabs) からデータをバックアップまたはエクスポートしてください。そうしないと、データは完全に失われます。
> 各APIコールエントリに関連するすべての入力/出力履歴も削除されます。

<a id="api-config"></a>
### API設定

サポートされているプロバイダーは以下のとおりです：OpenRouter、OpenAI、Anthropic、Google Gemini、DeepSeek、Groq、Mistral、xAI、Cerebras、および**Ollama**（ベースURL経由のローカルモデル）。使用するプロバイダーのみを設定する必要があります。

**Webアプリケーション：管理者のみ**

APIキーはシステムまたはDockerの環境変数で設定します。Web UIに入力するものではありません。このページでは、どのプロバイダーにキーが設定されているかを確認でき、**`テスト`**ボタンをクリックしてそれぞれの接続をテストできます。

<br/>

> ℹ️ **注記**<br/>
> APIキーを変更するには、システムまたはDockerの設定で環境変数を更新し、サーバーまたはコンテナを再起動してください。

> ℹ️ **注記**<br/>
> **設定のバックアップ**（[**一般設定** → 設定のバックアップ](#general-settings)を参照）では、ZIP内の`config.json`に**解決済み**のプロバイダーキーを埋め込むことができます。そのZIPを復元しても、これらのキーはサーバーの永続化された設定ファイルにコピーされません。実行中のキーは、前述の通り、引き続き環境変数および既存のファイル状態から取得されます。

<br/>

**デスクトップアプリケーション**

使用する各プロバイダーのAPIキーを**API設定**に保存します。Ollamaの場合は、APIキーの代わりに**ベースURL**を入力します。

<br/>

> 💡 **ヒント** <br/>
> APIキーの使用や課金を避けたい場合は、[Ollamaをダウンロード](https://ollama.com)して、`translategemma:4b`などのモデルをマシン上で無料でローカル実行できます。また、クレジットカード不要の無料OpenRouterアカウントを作成して無料モデルを利用したり、Cerebras、Google、Groq、Mistral AIから無料のAPIキーを取得することもできます。

<br/>

- 必要なプロバイダーのみを追加してください。**設定** > **モデル**では、各モデルIDはプロバイダー名で始まります（例：`openrouter/openrouter/free`、`openai/gpt-4o`、`ollama/llama3`）。

APIキーを追加するには、テキストフィールドに値を入力して**`保存`**ボタンをクリックします。既存のキーを変更するには**`編集`**ボタンをクリックします。キーが正常に機能しているか確認するには、**`テスト`**ボタンをクリックします。OllamaのベースURLの場合は、接続確認のために常に**`テスト`**をクリックしてください。

<br/>

> ℹ️ **注記**<br/>
> 現在のAPIキーの値を表示することはできません。**`編集`**ボタンを使用してのみ、キーを置き換えることができます。
> APIキーは設定内に暗号化されて保存されます。

<a id="common-issues"></a>
## よくある問題

何かが期待通りに動作しない場合は、まず以下の点を確認してください。

<br/>

<a id="the-app-will-not-translate-rewrite-or-transform-text"></a>
### アプリがテキストを翻訳、リライト、または変換しない

以下の点を確認してください：

- ツールバーでモデルが選択されていること
- [**設定** > **モデル**](#models) に少なくとも1つのモデルがリストされていること
- APIの設定が正常に動作していること

デスクトップアプリを使用している場合：

1. [**設定** > **API設定**](#api-config) を開きます。
2. 少なくとも1つのAPIキーが保存されていることを確認します。
3. プロバイダー横の **テスト** をクリックして、キーが正常に機能していることを確認します。

<br/>

<a id="the-model-list-is-empty"></a>
### モデルリストが空です

[**設定** > **モデル**](#models) を開き、**更新** をクリックします。

必要に応じて：

- モデルを検索する
- **無料のみ** をオンにする
- 1つ以上のモデルを **選択済みモデル** に追加する

<br/>

<a id="the-result-is-too-slow-or-too-expensive"></a>
### 結果が遅すぎる、または高すぎる

以下のいずれか、または複数を試してください：

- 異なるモデルを選択する
- 入力テキストを短くする
- [**設定** > **一般設定**](#general-settings) で **リアルタイム翻訳（入力中）** をオフにする
- 単純なタスクには無料モデルを使用する（[モデル](#models) を参照）

<br/>

<a id="the-interface-is-in-the-wrong-language"></a>
### インターフェースの言語が間違っている

[ツールバー](#toolbar) の地球儀アイコンをクリックし、希望の **インターフェース言語** を選択してください。

<br/>

<a id="the-text-is-too-small-or-hard-to-read"></a>
### テキストが小さすぎる、または読みづらい

[**設定** > **一般設定**](#general-settings) を開き、以下を変更してください：

- **フォントファミリー**
- **サイズ**

<br/>

<a id="dashboard-charts-are-empty"></a>
### ダッシュボードのチャートが空です

以下の場合は、これが正常です：

- **無料モデル** のみを使用しており、**コスト** の数値を確認している場合（コストがゼロになる可能性があります）。**概要** の **使用回数** のチャートは、選択した期間のデータが必要です
- 選択した **時間フィルター** がコールが行われた期間をカバーしていない場合 — 確認するには **すべて** を試してください

チャートが**すべて**を選択してもまだ空の場合は、[**履歴**](#history)または**全コール**タブにコールが表示されていることを確認してください。

<br/>

<a id="cost-shows-not-available-or-seems-wrong"></a>
### コストが「利用不可」と表示される、または正しくないように見える

**OpenRouter**を通じてモデルを使用している場合、アプリはOpenRouterから報告された実際の支出を表示します。

**その他のプロバイダー**（OpenAI直接、Anthropic直接など）については、コストはOpenRouterが公開している価格データから**推定**されます。モデルに一致する価格が見つからない場合、コストは**利用不可**と表示され、合計に加算されません。

<br/>

<a id="total-cost-does-not-match-my-provider-bill"></a>
### 合計コストがプロバイダーの請求額と一致しない

アプリ内のすべてのコスト数値は、**参考用の推定値**であり、公式の請求書ではありません。

合計を実際のOpenRouterの支出により近づけるには、[**設定** > **コスト追跡**](#cost-tracking)を開き、「APIキー使用量と同期」をクリックしてください。

<br/>

<a id="the-history-page-is-missing-from-the-sidebar"></a>
### サイドバーから履歴ページが消えている

**実行履歴を保存**がオフになっている可能性があります。[**設定** > **一般設定**](#general-settings)を開いて有効にしてください。オンにしても、以前に削除された履歴データは復元されないことに注意してください。

<br/>

<a id="web-app-session-expired"></a>
### Webアプリ：予期せずログインページにリダイレクトされる

セッションがタイムアウトした可能性があります。再度ログインしてください。頻繁に発生する場合は、サーバーの設定でセッションの有効期間を確認してください。

<br/>

<a id="web-admin-forgot-or-lost-a-password"></a>
### Web管理者：パスワードを忘れた、または紛失した

これはデスクトップ（Electron）アプリではなく、**セルフホスト型Webアプリ**（Docker）に該当します。

- 別の管理者がまだサインインできる場合は、[**設定** > **ユーザー**](#users)を開き、アカウントを選択してそこで**新しいパスワード**を設定できます。
- **ロックアウト**されているがマシンまたはコンテナに**シェルアクセス**がある場合は、イメージに同梱されているヘルパーを使ってパスワードをリセットします（デフォルト名を変更した場合は`transrewrt`を置き換えてください。パスワードにスペースや特殊文字が含まれる場合はクォートで囲んでください）：

```bash
docker exec transrewrt reset-web-password '<username>' '<new-password>'
```

他のアカウントを作成していない場合、デフォルトの管理者ユーザー名は`admin`です。引数を1つだけ渡すと、それは`admin`の新しいパスワードとして扱われます。

Dockerではなく**ソースコードのチェックアウト**から実行している場合は、以下を使用してください：

```bash
pnpm run reset-web-password -- <username> <new-password>
```

このスクリプトはSQLiteデータベースのユーザー情報を更新します（`admin`ユーザーが存在しない場合は作成も可能です）。リセット後は、新しいパスワードでサインインしてください。

<br/>

<a id="dashboard-shows-no-data-for-other-users"></a>
### ダッシュボードに他のユーザーのデータが表示されない（Web）

**管理者**のみが**ユーザー**フィルターを使用してすべてのユーザーのデータを表示できます。通常のユーザーは、設計上、自身の活動のみが表示されます。

<br/>

<a id="i-changed-a-prompt-and-lost-the-edits"></a>
### プロンプトを変更したが、編集内容が失われた

プロンプトを編集する際は、必ず**保存**をクリックしてから**実行に戻る**をクリックしてください。

<a id="quick-tips"></a>
## クイックヒント

- [**翻訳**](#translate)から始めることで、設定が正しく動作するか確認してから、[**リライト**](#rewrite)や[**変換**](#transform)に進んでください。
- 日常的な文章の改善には[**リライト**](#rewrite)を使用してください。
- 特定のタスクに対して繰り返し使えるワークフローが必要な場合は[**変換**](#transform)を使用してください。
- 使用状況や**コスト**を確認したい場合は[**ダッシュボード**](#dashboard)を使用してください。
- 過去の操作およびその完全な**入力**／**出力テキスト**を確認するには[**履歴**](#history)を使用してください。
- プロンプトライブラリを作成して安全に保管したい場合や、他者と共有したい場合は、定期的にプロンプトを**エクスポート**してください（[変換プロンプト](#transform-prompts)を参照）。
