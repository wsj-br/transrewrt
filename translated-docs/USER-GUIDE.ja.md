# ユーザーガイド

<br/>

<a id="introduction"></a>
## 導入

Transrewrt は、テキストを以下の3つの方法で処理するのに役立ちます。

- **翻訳** - テキストをある言語から別の言語に変換する。
- **書き直し** - より明確に、短く、またはよりフォーマルなスタイルなど、異なるスタイルでテキストを言い換える。
- **変換** - プロンプトと呼ばれるカスタムAI指示を使用してテキストを処理する。

<br/>

このガイドでは、アプリのインストールと実行後の使い方について説明します。インストール手順については、メインの **[README](README.ja.md)** をご参照ください。

<br/>

> ℹ️ **注記**<br/>
> Transrewrt は、WindowsおよびLinux向けのデスクトップアプリとして、またセルフホスティング可能なWebアプリとして利用可能です。このガイドはアプリの日常的な使用方法に焦点を当てています。特定の機能がいずれか一方のバージョンにのみ適用される場合は、明確にマークしています。

<a id="before-you-start"></a>
## 始める前に

Transrewrt を使用するには、少なくとも1つのAIプロバイダーへのアクセスが必要です。対応しているプロバイダーは以下の通りです：[OpenRouter](https://openrouter.ai)（多数のモデルを統合）、OpenAI、Anthropic、Google Gemini、DeepSeek、Groq、Mistral、xAI、Cerebras、およびローカルモデル用の[Ollama](https://ollama.com)です。

開始するのに有料モデルを選択する必要はありません。OpenRouterのAPIキーを追加すると、アプリは自動的に組み込みの**無料** OpenRouterオプションを有効にします。これにより、すぐにテキストの翻訳、書き直し、変換を始めることができます。また、Cerebras、Google、Groq、またはMistral AIから無料のAPIキーを取得することもできます。

わかりやすく言うと：

- **モデル** とは、作業を行うAIエンジンのことです。モデルは**プロバイダー接頭辞**（例：`openrouter/…`、`openai/…`、`ollama/…`）付きで表示されます。
- **APIキー**（またはOllamaの場合は**ベースURL**）は、アプリがそのプロバイダーに接続するための手段です。

**デスクトップアプリ** を使用している場合は、使用する各プロバイダーに対して[**設定** > **API設定**](#api-config)でキーを追加してください。OpenRouterのみを使用する場合は、以下の「[APIキーの取得方法](#how-to-get-an-api-key-desktop-app)」を参照してください。APIキーを使用したくない場合は、[ollama.com](https://ollama.com)からOllamaをインストールして、`translategemma:4b`などのローカルモデルを使用できます。

**Web版** を使用している場合、サーバーの管理者が環境変数を使ってプロバイダーを設定するため、アプリ内に直接APIキーを入力することはできません。

<br/>

<a id="how-to-get-an-api-key-desktop-app"></a>
### 無料のOpenRouter APIキーを取得する方法（デスクトップアプリ）

デスクトップアプリを使用している場合は、以下の手順に従ってください。

1. Webブラウザで[OpenRouter](https://openrouter.ai)にアクセスします。
2. アカウントを作成またはサインインします。
3. [Keys](https://openrouter.ai/keys)ページを開きます。
4. 新しいAPIキーを作成するボタンをクリックします。
5. 後で識別できるように、キーに名前を付けます。
6. 新しいAPIキーをコピーします。
7. Transrewrtに戻り、**設定** > **API設定** を開きます。
8. **OpenRouter APIキー**（**設定** > **API設定** 内）にキーを貼り付けます。
9. **OpenRouterキーをテスト** をクリックして、正しく動作するか確認します。

<br/><br/>

<a id="getting-started"></a>
## はじめに

初めてTransrewrtを使用する場合は、以下の順序で進めてください。

1. アプリを開きます。
2. 必要に応じて、地球儀アイコンから**インターフェース言語** を選択します。
3. **デスクトップアプリ** を使用している場合は、[**設定** > **API設定**](#api-config)を開き、少なくとも1つのプロバイダー（例：OpenRouter）のAPIキーを追加し、**テスト** をクリックして正しく動作するか確認します。
4. [**設定** > **モデル**](#models)を開き、1つ以上のモデルを**選択されたモデル** に追加します。
5. [**設定** > **言語**](#languages)を開き、よく使う言語を上位に表示させたい場合は**トップ言語** を選択します。
6. **翻訳** に移動し、簡単な翻訳を実行して、すべてが正しく動作していることを確認します。
7. それが成功したら、次に**書き直し**、その後**変換** を試してください。

この順序は重要です。最も一般的な初回使用時の問題（API接続や選択されたモデルがない状態でタスクを実行しようとする）を防ぐことができます。

<a id="toolbar"></a>
### ツールバー

ツールバーは、アプリ内の位置によってわずかに変化します。

- 左側には現在のページ名が表示されます。
- 右側には**モデルセレクター** と**インターフェース言語** のコントロールが表示されます。

**モデルセレクター** を使用すると、現在のタスクで使用するAIエンジンを選択できます。

![Model selector](../images/screenshots/ja/model-selector.png)

一部の無料モデルは常に利用可能とは限らず、オフラインになっている場合や使用制限がある場合があります。その場合、アプリは自動的にそのモデルを利用可能なリストから削除します。表示されるモデルを制御するには、[**設定** > **モデル**](#models)に移動してモデルリストを編集してください。

<br/>

**グローブアイコン + 言語コード** は、メニューやボタンなどのアプリのインターフェース言語を変更します。**翻訳** で使用される翻訳言語は**変更されません**。

![Interface language selector](../images/screenshots/ja/language-selector.png)

<a id="input-and-output-panels"></a>
### 入力および出力パネル

ほとんどのワークスペースでは、左側に**入力** パネル、右側に**出力** パネルを使用します。

各パネルには以下も表示されます：

| **入力**                                                          | **出力**                                                                                                                  |
|--------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| - 文字数 <br/>- 単語数 <br/>- 段落数 <br/> | - タスクに要した時間<br/>- **TPS**（1秒あたりのトークン数）<br/>- 文字数、単語数、段落数<br/>- 使用されたモデル |

技術用語について疑問がある場合：

- **トークン** とは、テキストの小さな断片を意味します。単語の一部または短い単語と考えてください。
- **TPS** とは、モデルが1秒間に処理したテキストの断片の数を意味します。

<br/>

また、各操作のコスト（利用可能な場合）および合計コストを[**設定** > **一般設定**](#general-settings)で`Show cost information on the actions`オプションを有効にすることで監視できます。

<a id="translate"></a>
## 翻訳

**翻訳** を使用すると、テキストをある言語から別の言語に変換できます。

![Translate workspace](../images/screenshots/ja/translate.png)

<br/>

<a id="translate-text"></a>
### テキストの翻訳

1. **翻訳** を開きます。
2. **From** で言語を選択します。
3. **To** で言語を選択します。
4. ツールバーでモデルを選択します。
5. **入力** にテキストを入力または貼り付けます。
6. **翻訳** をクリックします。
7. **出力** で結果を確認します。
8. 結果をコピーする場合は、コピーボタンを使用します。

<br/>

<a id="language-selection"></a>
### 言語の選択

- **From** は特定の言語または**言語を検出** にできます。
- **To** は、結果を出力したい言語です。

選択した**トップ言語** はリストの上部に表示されます。これらは[**設定** > **言語**](#languages)で設定できます。

<br/>

<a id="helpful-translation-settings"></a>
### 役立つ翻訳設定

[**設定** > **一般設定**](#general-settings)で、翻訳の動作方法を変更できます：

- **貼り付け時に自動翻訳**：テキストを貼り付けた直後に翻訳を実行します。
- **結果を自動的にクリップボードにコピー**：処理が成功した後、結果を自動的にクリップボードにコピーします。
- **リアルタイム翻訳（入力中）**：入力中に翻訳を実行します。
- **タイムアウト (ms)**：リアルタイム翻訳を実行する前にアプリが待機する時間を制御します。
- **Enter**：`Enter`キーを押したときに何が起こるかを制御します。

<a id="rewrite"></a>
## 書き直し

主な意味を変更せずに語句を改善したい場合に**書き直し** を使用します。

![Rewrite workspace](../images/screenshots/ja/rewrite.png)

これは次のような場合に便利です。

- スペルと文法の修正（**スペルと文法をチェック**）
- テキストの明確化（**明確さを向上**）
- 1回の実行で複数の異なる言い換えを生成（**代替バージョン**）
- テキストをよりフォーマルまたはカジュアルにする（**フォーマル** / **インフォーマル**）
- テキストを短くまたは長くする（**短くする** / **拡張する**）
- テキストをより専門的にする（**専門的にする**）

<br/>

> 💡 **ヒント**<br/>
> 「**スペルと文法をチェック**」モードを使用すると、出力パネルの（**コピー** の横にある）**変更を表示** スイッチが表示されます。
> これをオンまたはオフにすることで、テキストに適用された特定の修正を表示または非表示にできます。

<a id="transform"></a>
## 変換

AIにカスタムの指示セットに従って処理させたい場合に**変換** を使用します。

![Transform workspace](../images/screenshots/ja/transform.png)

これはアプリの中で最も柔軟性のある領域です。次のようなタスクに使用できます。

- メモの要約
- ざっくりとしたテキストを洗練されたメールに変換
- 主要ポイントの抽出
- テキストを特定の形式に変換
- 入力テキストを使ったその他のカスタム処理

<br/>

<a id="run-an-existing-prompt"></a>
### 既存のプロンプトを実行

1. **変換** を開きます。
2. プロンプトリストからプロンプトを選択します。
3. **ターゲット** 言語ボックスが表示された場合は、必要に応じて言語を選択します。
4. **入力** にテキストを入力または貼り付けます。
5. **変換** をクリックします。
6. **出力** で結果を確認します。

<br/>

<a id="if-you-have-no-prompts-yet"></a>
### プロンプトがない場合

プロンプトリストが空の場合は、変換ワークスペースで**サンプルプロンプトを読み込む** をクリックしてください。同じコントロールは[**設定** > **変換プロンプト**](#transform-prompts)のエクスポート/インポート行にも常にあります。どちらも組み込みの例を追加するため、すぐに始められます。

<br/>

> ℹ️ **注**<br/>
> サンプルプロンプトは英語で提供されています。読み込んだ後、プロンプトを編集し、**プロンプトを翻訳** を使用してあなたの言語に翻訳できます。

<br/>

<a id="create-a-prompt-quickly"></a>
### 簡単にプロンプトを作成

プロンプトをすばやく作成する最も簡単な方法は次のとおりです。

1. **新しいプロンプト** をクリックします。
2. **プロンプトを生成** をクリックします。
3. プロンプトに何をさせたいかを説明します。
4. モデルを選択します。
5. アプリがドラフトを作成するのを待ちます。
6. ドラフトを確認し、**保存** をクリックします。

![Generate prompt](../images/screenshots/ja/transform-generate.png)

<br/>

<a id="edit-a-prompt"></a>
### プロンプトを編集する

プロンプトを作成または編集する際、エディターが左側に表示され、右側にテスト領域が表示されます。

![Transform prompt editor](../images/screenshots/ja/transform-prompt-edit.png)

主なフィールドは以下のとおりです。

- **プロンプト名**: プロンプト一覧に表示される名前です。
- **プロンプトの指示（任意）**: プロンプト実行時にユーザーに表示される短いヒントです。
- **モデルの役割**: AIに割り当てられる全体的な役割です。たとえば「あなたは役立つアシスタントです。」などがあります。
- **モデルの指示（1行につき1つ）**: AIに従ってほしい特定のルールです。
- **出力の説明**: 結果を表す短い単語です。たとえば「概要」や「書き直し」などがあります。
- **温度 (0.0 → 1.0)**: モデルの動作方法を示します。詳細は以下をご覧ください。
- **対象言語を尋ねる**: プロンプト実行時にターゲット言語の選択肢を追加します。

技術用語の **温度** が初めての方は、次のように考えてください。

- **低い** 温度では、安定しており予測しやすい結果になります。
- **高い** 温度では、より多様で創造的な結果になります。

また、以下の機能も使用できます。

- **`Generate prompt`** を使用して、簡単な説明から新しいドラフトを作成する
- **`Improve prompt`** を使用して、既存のプロンプトを洗練する
- **`Translate prompt`** を使用して、プロンプトのフィールドを翻訳する

<br/>

> ⚠️ **警告**<br/>
> **`Back to Run`** をクリックする前に **`Save`** をクリックしてください。保存せずに戻った場合、変更内容は失われます。

<a id="general-settings"></a>
### 一般設定

**一般設定** を使用して、入力時の動作、**履歴** に実行詳細を保存するかどうか、および外観を制御します。

**動作**

- **ENTERの動作** では、`Enter`がタスクを実行するか、改行を挿入するかを選択します。
- **貼り付け時に自動翻訳** は、テキストを貼り付けた直後に翻訳を開始します。
- **結果を自動的にクリップボードにコピー** は、成功した結果を自動的にコピーします。
- **リアルタイム翻訳（入力中）** は、入力中に翻訳を行います。
- **タイムアウト（ミリ秒）** は、リアルタイム翻訳の待機時間を設定します。

**履歴**

- **実行履歴を保持** は、翻訳、書き直し、変換の各操作について、**入力および出力テキスト** をサイドバーの [**履歴**](#history) ビューに保存するかどうかを制御します。オフにすると確認が求められ、確認した場合、保存された履歴テキストがデータベースから削除されます。
- **履歴データを削除** は、**削除データ** を使用して、期間（たとえば数か月以上前など）または **すべてのデータ（クリア）** に基づいて保存されたテキストを削除できます。これは **履歴** ビューの保存された実行テキストにのみ影響し、**コスト** や使用量の合計は削除しません。**コスト** データを削除または削減するには、[**設定** > **コスト追跡**](#cost-tracking) を使用してください。

**外観**

- **アクションにコスト情報を表示** は、操作ごとのコスト（利用可能な場合）および翻訳、書き直し、変換の出力パネルにおける合計コストの表示を制御します。
- **コスト小数桁数** は、コストの小数点以下の表示方法を変更します。
- **Webのみ：** **アプリの周囲に余白を表示** は、インターフェースの周囲に余白を追加します。
- **フォントファミリー** は、テキストパネル内のフォントを変更します。
- **サイズ** は、フォントサイズを変更します。

**設定のバックアップ**

- **バックアップに使用データを含める** - 有効にすると、ZIPファイルには実行履歴およびAPI呼び出しデータも含まれます。
- **設定をバックアップ** - 単一のZIPファイル（デフォルトでUTCの`transrewrt-config-backup-YYYY-MM-DD_HHMMSS.zip`）を作成します。これには`config.json`、`state.json`、任意の暗号化キー、ユーザー、設定、カスタムプロンプト、および使用データ（選択した場合）が含まれます。バックアップが成功すると、確認画面に保存されたファイル名が表示されます。
- **バックアップから復元** - 最初に **確認ダイアログ** を開きます。ダイアログ内でバックアップZIPを選択（**参照** / ファイルピッカー、またはサポートされている場合はドラッグ＆ドロップ）、次にオプションを確認します：
  - **使用データを復元** - 使用データを含めてバックアップされた場合、ZIP内の使用履歴をインポートします。設定とプロンプトのみを復元したい場合は、このオプションをオフにします。
  - **復元する前に古い使用データをクリア** - バックアップを適用する前に、このインストールの既存の使用履歴を削除します（任意。完全に置き換えたい場合に使用）。

デスクトップ版またはWeb版で作成されたバックアップは、いずれも他方のバージョンで復元できます。デスクトップ版のバックアップをWeb版で復元する場合、データは管理者ユーザーに復元されます。

<br/>

<a id="models"></a>
### モデル

**設定** > **モデル** を使用して、ツールバーに表示されるモデルを選択します。

![Settings Models tab](../images/screenshots/ja/settings-models.png)

このページには2つのリストがあります：

- 左側の**利用可能なモデル**
- 右側の**選択されたモデル**

便利なコントロールには以下があります：

- **モデルを検索...** を使用して、名前でモデルを検索
- **プロバイダー** のチップを使って、リストを1つのエンジン（OpenRouter、OpenAI、Ollamaなど）に絞り込む
- **無料のみ** で、無料モデルのみを表示
- **更新** でリストを再読み込み
- プロバイダー別に並べ替えているときに使用する**すべて展開** および**すべて折りたたむ**

モデルIDにはプロバイダーの接頭辞が含まれます（たとえば`openrouter/…`と`openai/…`）。**OpenAI (OpenRouter)** や **OpenAI (ダイレクト)** などのバッジは、トラフィックがどのようにルーティングされるかを示しています。

> ℹ️ **注記**<br/>
> **OpenRouter Body Builder**（`openrouter/bodybuilder`）は汎用チャットモデルではなくルーターモデルです。このモデルの応答は、OpenRouter APIリクエストボディを記述するJSON（たとえば、`requests`と`model`を含む`messages`配列）になります。このモデルを**翻訳**、**書き直し**、または**変換** に使用すると、出力パネルには完成したテキストではなくそのJSONが表示されます。これらのタスクには通常のテキストモデルを選択してください。詳しくはOpenRouterの[Body Builderモデルページ](https://openrouter.ai/openrouter/bodybuilder)を参照してください。

操作：

- モデルを追加するには、**追加** ボタンをクリックするか、エントリの任意の場所をクリックします。

- モデルを削除するには、**選択されたモデル** 内の該当モデル横の**X** ボタン、または利用可能なモデルのエントリにある**選択済み** をクリックします。

- リストをクリアするには、**すべて選択解除** をクリックします。必須の無料モデルはリストに残ります。

<br/>

> ℹ️ **注記**<br/>
> OpenRouterにすぐにクレジットを追加したくない場合は、まず**無料のみ** を有効にして無料モデルを選択してください（クレジットカード不要）。また、Ollamaを使用してAPIキーなしでローカルでモデルを実行することもできます。

<br/>

<a id="cost-tracking"></a>
### コスト追跡

**設定** > **コスト追跡** を使用して、コスト情報の管理を行います。

- **合計コスト** は現在の累計を表示します。
- **値をコピー** で、合計をクリップボードにコピーします。
- **コストをリセット** で、保存された合計をゼロにリセットします。
- **APIキー使用状況との同期** で、合計をOpenRouterアカウントで報告された使用量に合わせます（OpenRouterのみ）。
- **APIキー使用状況** は、利用可能な場合、OpenRouterの使用詳細を表示します。
- **コストデータを削除** で、すべてのデータ、または選択した日付より前のエントリのみを削除します。

**コスト追跡：** OpenRouterモデルを使用すると、アプリはOpenRouterからのコスト情報に基づいて、実際の使用量と支出を表示します。その他のすべてのプロバイダーについては、アプリはOpenRouterが公開している価格を使用してコストを推定します。価格が利用できない場合、推定値はゼロになることがあります。

<br/>

> ℹ️ **注記**<br/>
>  **すべてのコスト数値は参考用の推定値であり、公式な請求書ではありません。**

<br/>

> ⚠️ **警告**<br/>
> データの削除は元に戻せません。削除する前に、[**履歴**](#history) または [**ダッシュボード** > **すべての呼び出し**](#dashboard-tabs) からデータをバックアップまたはエクスポートしてください。そうしないと、データは完全に失われます。
> 各API呼び出しエントリに関連するすべての入力/出力履歴も削除されます。

### API設定

サポートされているプロバイダーは以下のとおりです：OpenRouter、OpenAI、Anthropic、Google Gemini、DeepSeek、Groq、Mistral、xAI、Cerebras、および**Ollama**（ベースURL経由のローカルモデル）。使用するプロバイダーのみを設定すればよいです。

**Webアプリケーション：管理者のみ**

APIキーはシステムまたはDockerの環境変数で設定されます。Web UIに入力するものではありません。このページでは、どのプロバイダーにキーが設定されているかを確認でき、**`Test`** ボタンをクリックしてそれぞれのテストができます。

> ℹ️ **注記**<br/>
> **設定のバックアップ**（[**一般設定** → 設定のバックアップ](#general-settings)を参照）は、ZIP 内の `config.json` に**解決済み** のプロバイダーキーを埋め込む可能性があります。その ZIP を復元しても、これらのキーはサーバーの永続化された設定ファイルへ**コピーされません**。有効なキーは、前述の通り、環境および既存のファイル状態から引き続き取得されます。

<br/>

**デスクトップアプリケーション**

**API設定** を使用して、使用する各プロバイダーのAPIキーを保存します。Ollamaの場合は、APIキーの代わりに**ベースURL** を入力します。

<br/>

> 💡 **ヒント** <br/>
> APIキーを使用したくない場合や使用料を支払いたくない場合は、[Ollamaをダウンロード](https://ollama.com)して、マシン上で（たとえば`translategemma:4b`などの）モデルを無料でローカルに実行できます。また、クレジットカード不要の無料OpenRouterアカウントを作成して無料モデルを利用することもできます。あるいは、Cerebras、Google、Groq、Mistral AIから無料のAPIキーを取得することもできます。

<br/>

- 必要なプロバイダーのみを追加してください。**設定** > **モデル** では、各モデルIDはプロバイダー名で始まります（例：`openrouter/openrouter/free`、`openai/gpt-4o`、`ollama/llama3`）。

APIキーを追加するには、テキストフィールドに値を入力して **`Save`** をクリックしてください。既存のキーを置き換えるには、**`Edit`** をクリックしてください。キーが正常に機能しているか確認するには、**`Test`** をクリックしてください。OllamaベースURLの場合は、常に接続を確認するために **`Test`** をクリックしてください。

<br/>

> ℹ️ **注**<br/>
> 現在のAPIキーの値を表示することはできません。**`Edit`** ボタンを使用して置き換えることのみ可能です。
> APIキーは設定内で暗号化されて保存されます。

<a id="common-issues"></a>
## よくある問題

何かが期待通りに動作しない場合は、まず以下の項目を確認してください。

<br/>

<a id="the-app-will-not-translate-rewrite-or-transform-text"></a>
### アプリがテキストを翻訳、書き直し、または変換しない

以下の点を確認してください：

- ツールバーでモデルが選択されていること
- [**設定** > **モデル**](#models) に少なくとも1つのモデルがリストされていること
- APIのセットアップが正常に機能していること

デスクトップアプリを使用している場合：

1. [**設定** > **API設定**](#api-config) を開きます。
2. 少なくとも1つのAPIキーが保存されていることを確認します。
3. プロバイダー横の **テスト** をクリックして、キーが正常に機能していることを確認します。

<br/>

<a id="the-model-list-is-empty"></a>
### モデルリストが空である

[**設定** > **モデル**](#models) を開き、**更新** をクリックします。

必要に応じて：

- モデルを検索する
- **無料のみ** を有効にする
- 1つ以上のモデルを **選択されたモデル** に追加する

<br/>

<a id="the-result-is-too-slow-or-too-expensive"></a>
### 結果が遅すぎる、または高すぎる

以下のいずれかを試してください：

- 異なるモデルを選択する
- より短い入力を使う
- [**設定** > **一般設定**](#general-settings) で **リアルタイム翻訳（入力中）** をオフにする
- 簡単なタスクには無料のモデルを使用する（[モデル](#models)を参照）

<br/>

<a id="the-interface-is-in-the-wrong-language"></a>
### インターフェースの言語が間違っている

[ツールバー](#toolbar) の地球儀アイコンをクリックし、希望の **インターフェース言語** を選択します。

<br/>

<a id="the-text-is-too-small-or-hard-to-read"></a>
### テキストが小さすぎる、または読みづらい

[**設定** > **一般設定**](#general-settings) を開き、以下を変更してください：

- **フォントファミリー**
- **サイズ**

<br/>

<a id="dashboard-charts-are-empty"></a>
### ダッシュボードのチャートが空です

以下の場合は、これが正常です：

- **無料モデル** のみを使用しており、**コスト** の数値を確認している場合（ゼロになる可能性があります）。**概要** の**使用回数** チャートも、選択された期間のデータが必要です。
- 選択された**時間フィルター** が呼び出しの実行期間をカバーしていない場合 - 確認するには**すべて** を選択してみてください

**すべて** を選択してもチャートが空のままである場合は、[**履歴**](#history)または**すべての呼び出し** タブに呼び出しが表示されるか確認してください。

<br/>

<a id="cost-shows-not-available-or-seems-wrong"></a>
### コストが「利用不可」と表示される、または正しくないように見える

**OpenRouter** を通じてモデルを使用している場合、アプリはOpenRouterから報告された実際の支出を表示します。

**他のプロバイダー**（OpenAIダイレクト、Anthropicダイレクトなど）の場合、コストはOpenRouterが公開している価格データから推定されます。モデルに一致する価格が見つからない場合、コストは**利用不可** として表示され、累計合計に追加されません。

<br/>

<a id="total-cost-does-not-match-my-provider-bill"></a>
### 合計コストがプロバイダーの請求額と一致しない

アプリ内のすべてのコスト数値は、**参考用の推定値** であり、公式の請求書ではありません。

合計を実際のOpenRouterの支出により近づけるには、[**設定** > **コスト追跡**](#cost-tracking)を開き、**APIキー使用状況との同期** をクリックしてください。

<br/>

<a id="the-history-page-is-missing-from-the-sidebar"></a>
### 履歴ページがサイドバーに表示されない

**実行履歴を保持** がオフになっている可能性があります。[**設定** > **一般設定**](#general-settings)を開き、これを有効にしてください。オンにしても、以前に削除された履歴データは復元されません。

<br/>

<a id="web-app-session-expired"></a>
### Webアプリ：予期せずログインページにリダイレクトされる

セッションがタイムアウトした可能性があります。再度ログインしてください。頻繁に発生する場合は、サーバーの設定でセッションの有効期間を確認してください。

<br/>

<a id="web-admin-forgot-or-lost-a-password"></a>
### Web管理者：パスワードを忘れた、または紛失した

これは**セルフホスト型Webアプリ**（Docker）に該当します。デスクトップ（Electron）アプリには該当しません。

- 別の管理者がまだサインインできる場合は、[**設定** > **ユーザー**](#users)を開き、アカウントを選択して**新しいパスワード** を設定できます。
- **ロックアウト** されているが、マシンまたはコンテナに**シェルアクセス** がある場合は、イメージに同梱されているヘルパーを使用してパスワードをリセットしてください（デフォルト名を変更した場合は`transrewrt`を置き換えてください。パスワードにスペースまたは特殊文字が含まれる場合は引用符で囲んでください）：

```bash
docker exec transrewrt reset-web-password '<username>' '<new-password>'
```

他のアカウントを作成していない場合、デフォルトの管理者ユーザー名は`admin`です。引数を1つだけ渡す場合、それは`admin`の新しいパスワードとして扱われます。

Dockerではなく**ソースチェックアウト** から実行する場合は、以下を使用してください：

```bash
pnpm run reset-web-password -- <username> <new-password>
```

このスクリプトはSQLiteデータベース内のユーザー情報を更新します（存在しない場合は`admin`ユーザーを作成することもできます）。リセット後は、新しいパスワードでサインインしてください。

<br/>

<a id="dashboard-shows-no-data-for-other-users"></a>
### ダッシュボードに他のユーザーのデータが表示されない（Web）

**管理者** のみが、**ユーザー** フィルターを通じてすべてのユーザーのデータを閲覧できます。通常のユーザーは、設計上、自身の活動データのみを表示できます。

<br/>

<a id="i-changed-a-prompt-and-lost-the-edits"></a>
### プロンプトを変更したが、編集内容が失われた

プロンプトを編集する際は、**実行に戻る** をクリックする前に必ず**保存** をクリックしてください。

<br/><br/>

<a id="quick-tips"></a>
## 便利なヒント

- [**翻訳**](#translate)から始めて、セットアップが正しく動作することを確認してから、[**書き直し**](#rewrite)や[**変換**](#transform)に進んでください。
- 日常的な文章の改善には[**書き直し**](#rewrite)を使用してください。
- 特定のタスクに対して繰り返し使えるワークフローが必要な場合は[**変換**](#transform)を使用してください。
- 使用状況やコストを確認したい場合は[**ダッシュボード**](#dashboard)を使用してください。
- 過去の操作とその完全な入力/出力テキストを確認するには[**履歴**](#history)を使用してください。
- プロンプトライブラリを作成していてそれを安全に保管したい場合、または他の人と共有したい場合は、定期的にエクスポートを行ってください（[変換プロンプト](#transform-prompts)を参照）。
