# 사용자 가이드

<br/>

<a id="introduction"></a>
## 소개

Transrewrt는 텍스트 작업을 수행하는 데 세 가지 핵심 기능을 제공합니다.

- **번역** - 한 언어에서 다른 언어로 텍스트를 변환합니다.
- **다시 쓰기** - 보다 명확하게, 짧게 또는 공식적인 등 다른 스타일로 문장을 재구성합니다.
- **변환** - 프롬프트라고 불리는 사용자 지정 AI 지시사항을 사용해 텍스트를 처리합니다.

<br/>

이 문서는 프로그램 설치 및 실행 후 사용 방법에 대해 설명합니다. 설치 관련 단계는 기본 **[README](README.ko.md)** 파일을 참조하세요.

<br/>

> ℹ️ **참고**<br/>
> Transrewrt는 Windows 및 Linux용 데스크톱 앱과 셀프호스팅 웹앱으로 제공됩니다. 이 문서는 앱의 일상적인 사용법을 중심으로 다룹니다. 특정 버전에만 해당되는 기능은 명확하게 표시합니다.

<a id="before-you-start"></a>

## 시작하기 전

Transrewrt를 사용하려면 최소한 하나 이상의 AI 제공업체에 접근할 수 있어야 합니다. 지원되는 제공업체는 [OpenRouter](https://openrouter.ai) (다양한 모델을 통합함), OpenAI, Anthropic, Google Gemini, DeepSeek, Groq, Mistral, xAI 및 로컬 모델용 [Ollama](https://ollama.com)입니다.

시작할 때 유료 모델을 선택할 필요는 없습니다. OpenRouter API 키를 추가하는 즉시 앱에서는 내장된 무료 OpenRouter 옵션이 자동으로 활성화됩니다. 이를 통해 바로 텍스트 번역, 재작성 및 변환을 시작할 수 있습니다.

쉽게 설명하면 다음과 같습니다:

- **모델**(model)은 작업을 수행하는 AI 엔진입니다. 모델은 **제공업체 접두사**(예: `openrouter/…`, `openai/…`, `ollama/…`)와 함께 표시됩니다.
- **API 키**(또는 Ollama의 경우 **기본 URL**)는 앱이 해당 제공업체에 연결할 수 있도록 해주는 수단입니다.

**데스크톱 앱**을 사용하는 경우 사용하는 각 제공업체에 대해 [**설정** > **API 구성**](#api-config)에서 키를 추가하세요. OpenRouter만 사용하는 경우 아래의 [API 키를 확보하는 방법](#how-to-get-an-api-key-desktop-app)을 참조하세요. API 키를 사용하고 싶지 않다면 [ollama.com](https://ollama.com)에서 Ollama를 설치하고 로컬 모델을 사용할 수 있습니다.

**웹 버전**을 사용하는 경우 서버 관리자가 환경 변수를 통해 제공업체를 설정하므로, 일반적으로 사용자가 직접 API 키를 입력하지 않습니다.

<br/>

<a id="how-to-get-an-api-key-desktop-app"></a>
### 무료 OpenRouter API 키 확보 방법 (데스크톱 앱)

다음은 데스크톱 앱을 사용할 때의 절차입니다:

1. 웹 브라우저에서 [OpenRouter](https://openrouter.ai)로 이동하세요.
2. 계정을 생성하거나 로그인하세요.
3. [Keys](https://openrouter.ai/keys) 페이지를 엽니다.
4. 새 API 키를 생성하는 버튼을 클릭하세요.
5. 나중에 키를 쉽게 식별할 수 있도록 이름을 지정하세요.
6. 새 API 키를 복사하세요.
7. Transrewrt로 돌아가 **설정** > **API 구성**을 엽니다.
8. **설정** > **API 구성**에 있는 **OpenRouter API 키**란에 키를 붙여넣으세요.
9. **OpenRouter 키 테스트**를 클릭하여 정상 작동하는지 확인하세요.

<br/>

> ℹ️ **참고**<br/>
> 신용카드 정보를 등록하지 않아도 OpenRouter의 무료 경로 또는 다른 무료 모델들을 사용할 수 있습니다. 대부분의 경우 유료 모델을 선택하지 않고도 Transrewrt를 사용하기에 충분합니다. 또는 API 키 없이 Ollama를 사용하여 로컬에서 모델을 실행할 수 있습니다.

<br/><br/>

<a id="getting-started"></a>
## 시작하기

Transrewrt를 처음 사용한다면 다음 순서대로 진행하세요:

1. 앱을 엽니다.
2. 필요 시 지구본 아이콘을 눌러 **인터페이스 언어**를 선택합니다.
3. **데스크톱 앱**을 사용 중이라면 [**설정** > **API 구성**](#api-config)을 열고 최소한 한 개 이상의 제공업체(예: OpenRouter)에 대한 API 키를 추가한 뒤 **테스트**를 클릭하여 작동 여부를 확인합니다.
4. [**설정** > **모델**](#models)을 열고 **선택된 모델**에 하나 이상의 모델을 추가합니다.
5. [**설정** > **언어**](#languages)를 열고 가장 자주 사용하는 언어가 목록 상단에 오도록 **주 언어**(Top languages)를 설정할 수 있습니다.
6. **번역**으로 이동하여 간단한 번역을 실행해 모든 것이 정상 작동하는지 확인합니다.
7. 정상 작동이 확인되면 다음으로 **재작성**을, 그다음 **변환**을 시도해 보세요.

이 순서는 중요합니다. 앱에 유효한 API 연결이나 선택된 모델이 없이 작업을 시도함으로써 발생하는 일반적인 초보자 문제를 방지할 수 있기 때문입니다.

<a id="input-and-output-panels"></a>
### 입력 및 출력 패널

대부분의 작업 공간은 왼쪽에 있는 **입력** 패널과 오른쪽에 있는 **출력** 패널로 구성됩니다.

**입력** 패널에는 다음이 표시됩니다:

- 글자 수
- 단어 수
- 문단 수

**출력** 패널에는 다음이 표시될 수 있습니다:

- 작업 소요 시간
- 해당 작업의 비용(사용 가능한 경우)
- 누적 총비용
- **TPS**(초당 처리된 토큰 수)
- 글자 수, 단어 수, 문단 수
- 사용된 모델

기술적인 용어가 궁금한 경우:

- **토큰**(token)은 작은 단위의 텍스트를 의미합니다. 하나의 단어 일부나 짧은 단어라고 생각할 수 있습니다.
- **TPS**는 모델이 1초당 처리한 텍스트 조각(토큰)의 개수를 의미합니다.

<a id="translate"></a>
## 번역

다른 언어로 텍스트를 변환하고자 할 때 **번역** 기능을 사용하세요.

![번역 작업 공간](../images/screenshots/ko/translate.png)

<br/>

<a id="translate-text"></a>
### 텍스트 번역 방법

1. **번역**을 엽니다.
2. **원본**에서 언어를 선택합니다.
3. **대상**에서 언어를 선택합니다.
4. 도구 모음에서 모델을 선택합니다.
5. **입력** 창에 텍스트를 입력하거나 붙여넣습니다.
6. **번역**을 클릭합니다.
7. **출력** 창에서 결과를 확인합니다.
8. 결과를 복사하려면 복사 버튼을 사용하세요.

<br/>

<a id="language-selection"></a>
### 언어 선택

- **원본**(From)은 특정 언어 또는 **언어 감지**가 될 수 있습니다.
- **대상**(To)은 결과를 원하는 언어입니다.

사용자가 설정한 **주요 언어**는 목록 상단에 표시됩니다. 이는 [**설정** > **언어**](#languages)에서 설정할 수 있습니다.

<br/>

<a id="helpful-translation-settings"></a>
### 유용한 번역 설정

[**설정** > **일반 설정**](#general-settings)에서 번역 동작 방식을 변경할 수 있습니다:

- **붙여넣을 때 자동 번역**: 텍스트를 붙여넣는 즉시 번역을 실행합니다.
- **결과 자동 복사**: 성공적으로 실행된 후 결과를 자동으로 클립보드에 복사합니다.
- **실시간 번역**(입력 중): 입력하는 도중에 번역이 실행됩니다.
- **제한 시간(밀리초)**: 실시간 번역을 실행하기 전에 앱이 기다리는 시간을 조정합니다.

<br/>

<a id="keyboard-shortcuts"></a>
### 키보드 바로 가기

[**설정** > **일반 설정**](#general-settings)의 **ENTER 동작**은 `Enter` 키를 누를 때의 동작을 제어합니다:

- **Enter** 키로 작업을 실행하고, **Shift+Enter** 키로 새 줄을 추가할 수 있습니다.
- 또는 반대로 설정할 수도 있습니다.

현재 모드는 **번역** 버튼에도 표시됩니다.

<a id="rewrite"></a>
## 다시 작성

주된 의미는 유지하면서도 표현 방식을 개선하고자 할 때 **다시 작성** 기능을 사용하세요.

![다시 작성 작업 공간](../images/screenshots/ko/rewrite.png)

이 기능은 다음 목적으로 유용합니다:

- 맞춤법 및 문법 수정
- 더 명확한 문장 만들기
- 더 공식적이거나 비공식적인 어투로 변경
- 텍스트 축약 또는 확장
- 더 기술적인 표현으로 바꾸기

<br/>

<a id="rewrite-text"></a>

### 텍스트 다시 작성하기

1. **다시 작성하기(Rewrite)**를 엽니다.
2. **모드(Mode)**를 선택합니다.
3. 도구 모음에서 모델을 선택합니다.
4. **입력(Input)**란에 텍스트를 입력하거나 붙여넣습니다.

6. **출력(Output)** 영역에서 결과를 확인합니다.

> 이 버튼을 클릭하여 수정 내용의 표시 여부를 전환하고, 텍스트에 적용된 변경 사항을 보이거나 숨길 수 있습니다.

<a id="transform"></a>
## 변환하기( Transform)

사용자 정의 지침을 AI에 따르게 하고 싶을 때 **변환하기(Transform)** 기능을 사용하세요.

![Transform 작업공간](../images/screenshots/ko/transform.png)

이 앱에서 가장 유연한 영역입니다. 다음과 같은 작업에 활용할 수 있습니다.

- 메모 요약하기
- 초안 텍스트를 다듬어 완성된 이메일로 만들기
- 주요 내용 추출하기
- 특정 형식으로 텍스트 변환하기

<br/>

<a id="run-an-existing-prompt"></a>
### 기존 프롬프트 실행하기

1. **변환하기(Transform)**를 엽니다.
2. 프롬프트 목록에서 프롬프트를 선택합니다.
3. **대상(Target)** 언어 상자가 나타나면, 필요 시 언어를 선택합니다.
4. **입력(Input)**란에 텍스트를 입력하거나 붙여넣습니다.
5. **변환(Transform)**을 클릭합니다.
6. **출력(Output)** 영역에서 결과를 확인합니다.

<br/>

<a id="if-you-have-no-prompts-yet"></a>
### 프롬프트가 없을 경우

프롬프트 목록이 비어 있는 경우, **샘플 프롬프트 불러오기(Load sample prompts)**를 클릭하세요. 미리 만들어진 예제들이 추가되어 빠르게 시작할 수 있습니다.

<br/>

> ℹ️ **참고(NOTE)**<br/>
> 샘플 프롬프트는 영어로 제공됩니다. 불러온 후에는 프롬프트를 편집하고 **프롬프트 번역하기(Translate prompt)** 기능을 사용해 사용자의 언어로 변역할 수 있습니다.

<br/>

<a id="create-a-prompt-quickly"></a>
### 빠르게 프롬프트 만들기

프롬프트를 만드는 가장 빠른 방법은 다음과 같습니다.

1. **새 프롬프트(New prompt)**를 클릭하세요.
2. **프롬프트 생성(Generate prompt)**을 클릭하세요.
3. 프롬프트가 해야 할 일을 설명합니다.
4. 모델을 선택합니다.
5. 앱이 초안을 자동으로 생성하도록 합니다.
6. 초안을 검토한 후 **저장(Save)**을 클릭합니다.

![프롬프트 생성하기](../images/screenshots/ko/transform-generate.png)


<br/>

<a id="edit-a-prompt"></a>
### 프롬프트 편집하기

자신의 프롬프트를 생성하거나 편집할 때 왼쪽에 편집기가 나타나고, 오른쪽에 테스트 영역이 표시됩니다.

![Transform 프롬프트 편집기](../images/screenshots/ko/transform-prompt-edit.png)

주요 항목은 다음과 같습니다.

- **프롬프트 이름(Prompt name)**: 프롬프트 목록에 표시되는 이름입니다.
- **프롬프트 지침(옵션)(Prompt instructions (optional))**: 프롬프트 실행 시 사용자에게 보여주는 짧은 안내 문구입니다.
- **모델 역할(Model Role)**: AI에게 할당된 전체 역할. 예: '도움이 되는 조수입니다.'
- **모델 지침(줄 당 하나)(Model Instructions (one per line))**: AI가 따라야 하는 구체적인 규칙입니다.
- **출력 설명(Output description)**: 결과를 간단히 설명하는 단어. 예: '요약(summary)' 또는 '다시 작성하기(rewrite)'.
- **온도(Temperature)(0.0 → 1.0)**: 모델의 행동 방식을 결정합니다. 아래 설명을 참조하세요.
- **대상 언어 요청하기(Ask for target language)**: 프롬프트 실행 시 대상 언어 선택기를 추가합니다.

기술 용어 **온도(Temperature)**가 처음이라면 다음처럼 이해하세요:

- **낮은** 온도는 더 일관되고 예측 가능한 결과를 제공합니다.
- **높은** 온도는 더 다양한 창의적인 결과를 제공합니다.

다음을 사용할 수도 있습니다:

- **`프롬프트 생성` (Generate prompt)**: 간단한 설명으로 새 초안 생성
- **`프롬프트 개선` (Improve prompt)**: 기존 프롬프트 세밀 조정
- **`프롬프트 번역` (Translate prompt)**: 프롬프트 필드 번역

<br/>

> ⚠️ **경고(WARNING)**<br/>
> **`돌아가기(Back to Run)`**를 클릭하기 전에 반드시 **`저장(Save)`**을 클릭하세요. 저장하지 않고 돌아가면 변경된 내용이 모두 사라집니다.

<br/>

<a id="test-a-prompt-before-using-it"></a>
### 사용 전 프롬프트 테스트하기

오른쪽에 있는 테스트 패널을 통해 실제 업무에 사용하기 전에 샘플 텍스트로 프롬프트를 시험해볼 수 있습니다.

다음과 같은 경우 유용합니다:

- 새 프롬프트를 만들고 있을 때
- 두 가지 버전의 프롬프트를 비교할 때
- 어조, 길이 또는 출력 형식을 확인하고 싶을 때

<br/>

<a id="manage-saved-prompts"></a>
### 저장된 프롬프트 관리하기

저장된 프롬프트를 한곳에서 관리하려면 [**설정(Settings)** > **Transform 프롬프트(Transform Prompts)**](#transform-prompts)를 열면 됩니다.

여기서 다음 작업이 가능합니다:

- 프롬프트 나열 및 삭제
- 프롬프트를 **JSON**, **CSV**, 또는 **XLSX** 형식으로 내보내기
- 파일에서 프롬프트 가져오기

<a id="general-settings"></a>

### 일반 설정

**일반 설정**을 사용하여 입력 동작, **기록**에 실행 세부 정보를 저장할지 여부 및 외형을 제어할 수 있습니다.

**동작**

- **ENTER 동작**: `Enter` 키를 눌렀을 때 작업을 실행할지, 새 줄을 삽입할지 선택합니다.
- **붙여넣기 시 자동 번역**: 텍스트를 붙여넣는 즉시 번역을 시작합니다.
- **결과 자동 클립보드 복사**: 성공적인 번역 결과를 자동으로 클립보드에 복사합니다.
- **실시간 번역(입력 중)**: 입력하는 도중 실시간으로 번역합니다.
- **제한 시간(ms)**: 실시간 번역을 위한 대기 시간을 설정합니다.

**기록**

- **실행 기록 유지**: 사이드바의 [**기록**](#history) 보기에서 **입력 및 출력 텍스트**를 저장할지 여부를 제어합니다. 기능을 끄면 확인을 요청하며, 확인 시 기록된 텍스트가 데이터베이스에서 제거됩니다.
- **기록 데이터 삭제**: **데이터 삭제**를 사용하여 기록된 텍스트를 나이별로(예: 몇 개월 이전 자료나 **모든 데이터(지우기)** ) 삭제할 수 있습니다. 이는 **기록** 보기의 저장된 실행 텍스트에만 영향을 미치며, 비용 또는 사용량 총합은 **삭제하지 않습니다**. **비용** 데이터를 제거하거나 축소하려면 [**설정** > **비용 추적**](#cost-tracking)을 사용하세요.

**외형**

- **비용 소수 자리수**: 비용 소수점 표시 방법을 변경합니다.
- **웹 전용**: **앱 주변에 여백 표시**를 선택하면 인터페이스 주변에 여유 공간이 추가됩니다.
- **글꼴** 텍스트 패널의 글꼴을 변경합니다.
- **크기**: 글꼴 크기를 조정합니다.

### 모델

**설정** > **모델**을 사용하여 도구 모음에 표시할 모델을 선택할 수 있습니다.

![설정 - 모델 탭](../images/screenshots/ko/settings-models.png)

페이지는 두 개의 목록으로 구성되어 있습니다:

- 왼쪽의 **사용 가능한 모델**
- 오른쪽의 **선택한 모델**

유용한 컨트롤:

- **모델 검색...**: 이름으로 모델을 찾습니다.
- **제공업체**(chips): 목록을 특정 엔진(OpenRouter, OpenAI, Ollama 등)으로 제한합니다.
- **무료 전용** 무료 모델만 표시합니다.
- **새로고침**: 목록을 다시 로드합니다.
- **모두 확장**, **모두 접기**: 제공업체별로 정렬할 때 사용합니다.

모델 ID는 제공업체 접두사를 포함합니다(예: `openrouter/…`, `openai/…`). **OpenAI (OpenRouter)** 또는 **OpenAI (직접)** 와 같은 배지 표시를 통해 트래픽이 어떻게 라우팅되는지 확인할 수 있습니다.

기능:

- 모델 추가: **추가** 버튼이나 목록에서 항목의 아무 곳이나 클릭하세요.
- 모델 제거: **선택한 모델** 목록에서 해당 항목 옆의 **X**를 클릭하거나 사용 가능한 모델 목록에서 항목의 **선택 해제**를 클릭하세요.
- 목록 지우기: **전체 선택 해제**를 클릭합니다. 무료 필수 모델은 목록에 유지됩니다.

<br/>

> ℹ️ **참고**<br/>
> OpenRouter에 곧바로 크레딧을 추가하고 싶지 않다면, 먼저 **무료 전용**을 활성화하고 무료 모델을 선택하세요(신용카드 없이도 사용 가능). Ollama를 사용하여 API 키 없이 로컬에서 모델을 실행할 수도 있습니다.

<br/>

<a id="languages"></a>
### 언어

**설정** > **언어**를 사용하여 앱에서 사용하는 언어 목록을 관리할 수 있습니다.

- **상위 언어**: **번역** 및 **변형** 화면의 언어 목록 상단에 고정됩니다.
- **사용자 정의 언어**: 내장 목록에 없는 언어를 추가할 수 있습니다.

사용자 정의 언어를 추가하면 내장된 옵션과 함께 언어 선택기에서 표시됩니다.

<br/>

<a id="cost-tracking"></a>
### 비용 추적

**설정** > **비용 추적**을 사용하여 비용 정보를 관리합니다.

- **총비용**: 누적된 비용을 표시합니다.
- **값 복사**: 총비용을 클립보드에 복사합니다.
- **비용 재설정**: 저장된 총비용을 0으로 초기화합니다.
- **API 키 사용량과 동기화**: OpenRouter 계정에서 보고된 사용량과 일치하도록 총비용을 설정합니다.(OpenRouter 전용)
- **API 키 사용량**: 사용 가능한 경우 OpenRouter 사용량 세부 정보를 표시합니다.
- **비용 데이터 삭제**: 모든 데이터 또는 선택한 날짜보다 오래된 항목만 제거합니다.

**비용 추적 설명**:
OpenRouter 모델을 사용하는 경우, 앱은 OpenRouter에서 제공하는 데이터에 따라 실제 사용량과 비용을 표시합니다. 그 외 제공업체의 경우, OpenRouter에서 공개한 요금표를 기반으로 비용을 예측하며, 요금 정보가 없는 경우 예상 비용이 0으로 표시될 수 있습니다.

<br/>

> ℹ️ **참고**<br/>
> 모든 비용 수치는 참고용 예상치이며 공식 청구서와는 다를 수 있습니다.

<br/>

> ⚠️ **경고**<br/>
> 데이터 삭제는 되돌릴 수 없습니다. 삭제 전 반드시 백업하거나 [**대시보드** > **모든 호출**](#dashboard-tabs)에서 내보내기하세요. 그렇지 않으면 데이터가 영구적으로 삭제됩니다. <br/> 각 API 호출 항목과 관련된 모든 기록도 함께 삭제됩니다.

<br/>

<a id="api-config"></a>
### API 설정

지원되는 제공업체는 OpenRouter, OpenAI, Anthropic, Google Gemini, DeepSeek, Groq, Mistral, xAI, 그리고 **Ollama**(기본 URL을 통한 로컬 모델)입니다. 사용하는 제공업체만 설정하면 됩니다.

**웹 애플리케이션: 관리자만 가능**

API 키는 시스템 또는 Docker 환경 변수를 통해 설정되며, 웹 UI에 직접 입력하지 않습니다. 이 페이지에서는 어떤 제공업체에 키가 설정되었는지를 확인할 수 있으며, 각각의 **`테스트`** 버튼을 클릭하여 작동 여부를 시험할 수 있습니다.

<br/>

> ℹ️ **참고**<br/>
> API 키를 변경하려면 시스템 또는 Docker 설정의 환경 변수를 업데이트하고 서버 또는 컨테이너를 재시작하세요.

<br/>

**데스크탑 애플리케이션**

사용하는 각 제공업체별 API 키를 저장하려면 **API 설정**을 사용하세요. Ollama의 경우 API 키 대신 **기본 URL**을 입력해야 합니다.


<br/>

> 💡 **팁** <br/>
> API 키를 사용하지 않거나 사용료를 지불하고 싶지 않다면, 무료로 [Ollama 다운로드](https://ollama.com)하여 컴퓨터에서 로컬로 모델을 실행할 수 있습니다. 또는 신용카드 없이 무료로 OpenRouter 계정을 생성하여 무료 모델을 사용할 수도 있습니다.

- 필요할 때만 제공업체를 추가하세요. **설정** > **모델**에서 각 모델 ID는 제공업체 이름으로 시작됩니다(예: `openrouter/openrouter/free`, `openai/gpt-4o`, `ollama/llama3`).

API 키를 추가하려면 텍스트 필드에 값을 입력하고 **`저장`**을 클릭하세요. 기존 키를 변경하려면 **`편집`**을 클릭하세요. 키가 제대로 작동하는지 확인하려면 **`테스트`**를 클릭하세요.

<br/>

> ℹ️ **참고**<br/>
> 저장된 API 키의 실제 값을 확인할 수 없습니다. 오직 **`편집`** 버튼을 통해 키를 교체할 수 있습니다.
> API 키는 구성 파일에 암호화되어 저장됩니다.

<br/>

OpenRouter 키를 발급받는 자세한 절차는 위의 [API 키를 받는 방법](#how-to-get-an-api-key-desktop-app)을 참조하세요.

<a id="common-issues"></a>
## 자주 발생하는 문제

예상대로 작동하지 않는 경우, 다음 항목을 먼저 확인하세요.

<br/>

<a id="the-app-will-not-translate-rewrite-or-transform-text"></a>
### 앱이 텍스트를 번역, 재작성 또는 변환하지 못함

다음 사항을 확인하세요:

- 툴바에서 모델을 선택했는가?
- [**설정** > **모델**](#models)에 최소한 하나 이상의 모델이 등록되어 있는가?
- API 설정이 올바르게 작동하는가?

데스크탑 앱을 사용 중이라면:

1. [**설정** > **API 설정**](#api-config)을 엽니다.
2. 최소한 하나 이상의 API 키가 저장되었는지 확인합니다.
3. 제공업체 옆의 **테스트** 버튼을 클릭하여 키가 제대로 작동하는지 확인합니다.

<br/>

<a id="the-model-list-is-empty"></a>
### 모델 목록이 비어 있음

[**설정** > **모델**](#models)을 열고 **새로 고침**을 클릭하세요.

필요 시:

- 모델을 검색하세요
- **무료 전용** 옵션을 활성화하세요
- 하나 이상의 모델을 **선택된 모델**에 추가하세요

<br/>

<a id="the-result-is-too-slow-or-too-expensive"></a>
### 결과가 너무 느리거나 비쌈

다음 조치 중 하나 이상을 시도해 보세요:

- 다른 모델을 선택하세요
- 입력 텍스트를 더 짧게 작성하세요
- [**설정** > **일반 설정**](#general-settings)에서 **입력 중 실시간 번역** 끄기
- 간단한 작업에는 무료 모델을 사용하세요 ([모델](#models) 참조)

<br/>

<a id="the-interface-is-in-the-wrong-language"></a>
### 인터페이스 언어가 잘못됨

[툴바](#toolbar)에 있는 지구본 아이콘을 클릭하고 원하는 **인터페이스 언어**를 선택하세요.

<br/>

<a id="the-text-is-too-small-or-hard-to-read"></a>
### 텍스트가 너무 작거나 읽기 어려움

[**설정** > **일반 설정**](#general-settings)을 열고 다음 설정을 변경하세요:

- **글꼴**
- **크기**

<br/>

<a id="dashboard-charts-are-empty"></a>
### 대시보드 차트가 비어 있음

다음 경우에는 이러한 현상이 정상입니다:

- 오직 **무료 모델**만 사용 중임 (비용 차트는 비어 있음)
- 선택한 **시간 필터**가 실제로 API 호출이 이루어진 기간을 포함하지 않음 — **전체 기간** 옵션으로 확인해 보세요

**전체 기간**을 선택했는데도 차트가 비어있을 경우, [**기록**](#history) 또는 **전체 호출** 탭에서 실제로 호출 기록이 표시되는지 확인하세요.

<br/>

<a id="cost-shows-not-available-or-seems-wrong"></a>

### 비용이 "사용할 수 없음"으로 표시되거나 잘못된 것처럼 보임

**OpenRouter**를 통해 모델을 사용할 경우, 앱은 OpenRouter에서 보고한 실제 비용을 표시합니다.

**기타 제공업체**(OpenAI 직접, Anthropic 직접 등)의 경우, 비용은 OpenRouter에서 공개한 가격 데이터 기반으로 추정됩니다. 모델에 해당하는 가격을 찾을 수 없는 경우 비용은 **사용할 수 없음**으로 표시되며, 누적 비용에 포함되지 않습니다.

<br/>

<a id="total-cost-does-not-match-my-provider-bill"></a>
### 총 비용이 제공업체의 청구서와 맞지 않음

애플리케이션의 모든 비용 수치는 **참고용 추정치**이며 공식 청구서가 아닙니다.

총비용을 실제 OpenRouter 사용 내역과 더 가깝게 맞추려면, [**설정** > **비용 추적**](#cost-tracking)을 열고 **API 키 사용량과 동기화**를 클릭하세요.

<br/>

<a id="the-history-page-is-missing-from-the-sidebar"></a>
### 사이드바에 기록 페이지가 누락됨

**실행 기록 유지** 기능이 꺼져 있을 수 있습니다. [**설정** > **일반 설정**](#general-settings)을 열고 활성화하세요. 단, 켜도 이전에 삭제된 기록 데이터는 복구되지 않습니다.

<br/>

<a id="web-app-session-expired"></a>
### 웹 앱: 예기치 않게 로그인 페이지로 리디렉션됨

세션이 만료되었을 수 있습니다. 다시 로그인하세요. 자주 발생한다면, 서버 설정에서 세션 수명 관련 옵션을 확인하세요.

<br/>

<a id="dashboard-shows-no-data-for-other-users"></a>
### 대시보드에 다른 사용자의 데이터가 표시되지 않음(웹)

**관리자**만 **사용자** 필터를 통해 모든 사용자의 데이터를 볼 수 있습니다. 일반 사용자는 설계상 본인의 활동만 볼 수 있습니다.

<br/>

<a id="i-changed-a-prompt-and-lost-the-edits"></a>
### 프롬프트를 수정했는데 편집 내용을 잃어버림

프롬프트를 편집할 때는 언제나 **뒤로 돌아가기**를 클릭하기 전에 반드시 **저장**을 클릭하세요.
