# 사용자 가이드

<br/>

<a id="introduction"></a>

## 소개

Transrewrt는 세 가지 주요 방식으로 텍스트 작업을 도와줍니다:

- **번역** - 텍스트를 한 언어에서 다른 언어로 변환합니다.
- **다시 작성** - 더 명확하게, 짧게 또는 더 격식 있게 같은 텍스트를 다른 스타일로 다시 표현합니다.
- **변환** - 프롬프트라 불리는 사용자 정의 AI 지침을 사용하여 텍스트를 처리합니다.

<br/>

이 문서는 앱을 설치하고 실행한 후 사용 방법을 설명합니다. 설치 절차에 대해서는 주요 **[README](README.ko.md)** 를 참고하세요.

<br/>

> ℹ️ **참고**<br/>
> Transrewrt는 Windows 및 Linux용 데스크톱 앱과 자체 호스팅 웹 앱으로 제공됩니다. 이 안내서는 앱의 일상적인 사용을 중심으로 설명합니다. 특정 버전에만 적용되는 내용은 명확하게 표시합니다.

<a id="before-you-start"></a>

## 시작하기 전에

Transrewrt를 사용하려면 최소한 하나 이상의 AI 제공업체에 접근할 수 있어야 합니다. 지원되는 제공업체는 다음과 같습니다: [OpenRouter](https://openrouter.ai) (다양한 모델을 통합함), OpenAI, Anthropic, Google Gemini, DeepSeek, Groq, Mistral, xAI, Cerebras 및 로컬 모델용 [Ollama](https://ollama.com)입니다.

사용을 시작하기 위해 유료 모델을 선택할 필요는 없습니다. OpenRouter API 키를 입력하는 즉시 앱은 내장된 **무료** OpenRouter 옵션을 자동으로 활성화합니다. 이를 통해 즉시 텍스트를 번역하고, 다시 작성하며, 변환할 수 있습니다. 또는, Cerebras, Google, Groq, 혹은 Mistral AI로부터 무료 API 키를 따로 확보할 수도 있습니다.

간단히 설명하면 다음과 같습니다:

- **모델**(model)이란 작업을 수행하는 AI 엔진을 의미합니다. 모델은 **제공업체 접두사**(provider prefix)와 함께 표시됩니다 (예: `openrouter/…`, `openai/…`, `ollama/…`).
- **API 키**(또는 Ollama의 경우 **기본 URL**(base URL))은 앱이 해당 제공업체에 연결하는 방법입니다.

**데스크톱 앱**을 사용하는 경우, 사용 중인 각 제공업체에 대해 [**설정** > **API 설정**](#api-config)에서 키를 추가하세요. OpenRouter만 사용하는 경우 아래의 [API 키를 확보하는 방법](#how-to-get-an-api-key-desktop-app)을 참조하세요. API 키를 사용하고 싶지 않다면 [ollama.com](https://ollama.com)에서 Ollama를 설치하여 `translategemma:4b`과 같은 로컬 모델을 사용할 수 있습니다.

**웹 버전**을 사용하는 경우, 서버 관리자가 환경 변수를 통해 제공업체를 설정하므로 앱 내에서 직접 API 키를 입력할 수 없습니다.

<br/>

<a id="how-to-get-an-api-key-desktop-app"></a>

### 무료 OpenRouter API 키를 얻는 방법(데스크톱 앱)

데스크톱 앱을 사용하는 경우, 다음 단계를 따르세요:

1. 웹 브라우저에서 [OpenRouter](https://openrouter.ai)로 이동합니다.
2. 계정을 생성하거나 로그인합니다.
3. [키](https://openrouter.ai/keys) 페이지를 엽니다.
4. 새 API 키를 생성하는 버튼을 클릭합니다.
5. 나중에 인식할 수 있도록 키에 이름을 지정합니다.
6. 새 API 키를 복사합니다.
7. Transrewrt로 돌아가 **설정** > **API 구성**을 엽니다.
8. **OpenRouter API 키**에 키를 붙여넣습니다(**설정** > **API 구성** 내).
9. 키가 잘 작동하는지 확인하기 위해 **OpenRouter 키 테스트**를 클릭합니다.

<br/><br/>

<a id="getting-started"></a>

## 시작하기

Transrewrt를 처음 사용하시는 경우 다음 순서를 따라 주세요:

1. 앱을 실행합니다.
2. 필요 시 구형 아이콘을 클릭해 **인터페이스 언어**를 선택합니다.
3. **데스크톱 앱**을 사용 중이라면 [**설정** > **API 설정**](#api-config)을 열고 하나 이상의 공급자(예: OpenRouter)에 대한 API 키를 추가한 후 **테스트**를 클릭해 정상 작동 여부를 확인합니다.
4. [**설정** > **모델**](#models)을 열고 하나 이상의 모델을 **선택된 모델**에 추가합니다.
5. [**설정** > **언어**](#languages)를 열어 가장 자주 사용하는 언어를 상단에 표시하고 싶다면 **상위 언어**를 선택합니다.
6. **번역**으로 이동하여 간단한 번역을 실행해 모든 기능이 정상적으로 작동하는지 확인합니다.
7. 이 작업이 완료되면 **다시 작성** 기능을 사용해 보고, 그 후 **변환** 기능을 시도합니다.

이 순서는 중요합니다. 앱이 작동 가능한 API 연결이나 선택된 모델을 가지기도 전에 작업을 실행하려는 가장 일반적인 초기 사용 문제를 방지할 수 있습니다.

### 툴바

앱에서 위치에 따라 툴바의 모양이 약간씩 달라집니다.

- 왼쪽에는 현재 페이지 이름이 표시됩니다.
- 오른쪽에는 **모델 선택기**와 **인터페이스 언어** 조정 기능이 있습니다.

**모델 선택기**를 사용하면 현재 작업에 사용할 AI 엔진을 선택할 수 있습니다.

  ![모델 선택기](../images/screenshots/ko/model-selector.png)

무료 모델 일부는 항상 이용 가능한 것은 아니며, 오프라인 상태이거나 사용량 제한이 있을 수 있습니다. 이런 경우 앱에서 해당 모델을 자동으로 사용 가능한 목록에서 제거합니다. 표시할 모델을 관리하려면 [**설정** > **모델**](#models)로 이동하여 모델 목록을 편집하세요.  
또한, 툴바에서 모델 이름 왼쪽의 제공업체 아이콘을 클릭하면 모델 설정을 바로 열 수 있습니다.

<br/>

**구체 아이콘 + 언어 코드**는 앱 인터페이스의 언어(예: 메뉴 및 버튼 등)를 변경합니다. 하지만 이 기능은 **번역** 기능에서 사용하는 번역 언어는 변경하지 않습니다.

<a id="input-and-output-panels"></a>

### 입력 및 출력 패널

대부분의 작업 공간에서는 왼쪽에 있는 **입력** 패널과 오른쪽에 있는 **출력** 패널을 사용합니다.

각 패널에는 다음과 같은 내용도 표시됩니다:

| **입력**                                                          | **출력**                                                                                                                  |
|--------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| - 글자 수 <br/>- 단어 수 <br/>- 문단 수                        | - 작업에 소요된 시간<br/>- **TPS**(초당 토큰 수)<br/>- 글자, 단어, 문단 수 통계<br/>- 사용된 모델 |

기술 용어가 궁금하다면 다음을 참고하세요:

- **토큰(Token)**은 작은 덩어리의 텍스트를 의미합니다. 단어의 일부 혹은 짧은 단어라고 생각할 수 있습니다.
- **TPS**는 모델이 초당 처리한 텍스트 덩어리의 개수를 의미합니다.

<br/>

또한 각 작업의 비용(가용한 경우) 및 총 비용을 [**설정** > **일반 설정**](#general-settings)에서 `작업에 비용 정보 표시` 옵션을 활성화하여 모니터링할 수 있습니다.

<a id="translate"></a>

## 번역

**번역** 기능은 텍스트를 한 언어에서 다른 언어로 변환하고자 할 때 사용합니다.

![번역 작업 공간](../images/screenshots/ko/translate.png)

<br/>

<a id="translate-text"></a>

### 텍스트 번역하기

1. **번역**을 엽니다.
2. **원본 언어**에서 언어를 선택합니다.
3. **대상 언어**에서 언어를 선택합니다.
4. 툴바에서 모델을 선택합니다.
5. **입력**란에 텍스트를 입력하거나 붙여넣습니다.
6. **번역**을 클릭합니다.
7. **출력**에서 결과를 확인합니다.
8. 결과를 복사하려면 복사 버튼을 사용하세요.

<br/>

<a id="language-selection"></a>

### 언어 선택

- **원본**은 특정 언어 또는 **언어 감지**일 수 있습니다.
- **번역**은 결과물로 원하는 언어입니다.

선택한 **주요 언어**는 목록 상단에 표시됩니다. 이는 [**설정** > **언어**](#languages)에서 설정할 수 있습니다.

<br/>

<a id="helpful-translation-settings"></a>

### 유용한 번역 설정

[**설정** > **일반 설정**](#general-settings)에서 번역 동작 방식을 변경할 수 있습니다.

- **붙여넣을 때 자동 번역**: 텍스트를 붙여넣는 즉시 번역을 실행합니다.
- **결과를 클립보드에 자동 복사**: 번역이 성공적으로 완료되면 결과를 자동으로 클립보드에 복사합니다.
- **실시간 번역 (입력 중)**: 입력하는 도중에 번역을 실행합니다.
- **시간 제한 (ms)**: 실시간 번역을 실행하기 전에 앱이 대기하는 시간을 설정합니다.
- **Enter 키 동작**: `Enter` 키를 눌렀을 때의 동작을 조정합니다.

<a id="rewrite"></a>

## 문장 개선

주요 의미는 유지하면서 문장의 표현을 개선하고 싶을 때 **문장 개선** 기능을 사용하세요.

![문장 개선 작업 영역](../images/screenshots/ko/rewrite.png)

이 기능은 다음 경우에 유용합니다:

- 맞춤법 및 문법 오류 수정 (**맞춤법 및 문법 검사**)
- 문장의 명확성 향상 (**명확성 개선**)
- 한 번의 실행으로 여러 가지 독립적인 재구성 제공 (**다른 버전 제시**)
- 문장을 더 격식 있게 또는 비격식적으로 변경 (**격식 있는** / **격식 없는**)
- 문장 줄이기 또는 확장 (**줄이기** / **확장하기**)
- 문장을 더 기술적으로 보이게 만들기 (**기술적 스타일로 변경**)

<br/>

> 💡 **TIP**<br/>

> 이 스위치를 켜거나 끔으로써 텍스트에 적용된 수정 내용을 보여줄지 아니면 숨길지를 결정할 수 있습니다.

<a id="transform"></a>

## 변환

사용자 지정 지침 집합을 따르도록 AI에 지시하고 싶을 때 **변환** 기능을 사용하세요.

![변환 작업 공간](../images/screenshots/ko/transform.png)

이 기능은 앱에서 가장 유연한 영역입니다. 다음과 같은 작업에 활용할 수 있습니다:

- 메모 요약하기
- 초안 글을 다듬어 완성된 이메일로 바꾸기
- 핵심 포인트 추출하기
- 텍스트를 특정 형식으로 변환하기
- 입력된 텍스트로 수행할 수 있는 기타 사용자 지정 작업

<br/>

<a id="run-an-existing-prompt"></a>

### 기존 프롬프트 실행하기

1. **변환(Transform)** 을 엽니다.
2. 프롬프트 목록에서 원하는 프롬프트를 선택합니다.
3. **대상(Target)** 언어 상자가 나타나면, 필요 시 언어를 선택합니다.
4. **입력(Input)** 에 텍스트를 입력하거나 붙여넣기합니다.
5. **변환(Transform)** 을 클릭합니다.
6. **출력(Output)** 에서 결과를 확인합니다.

<br/>

<a id="if-you-have-no-prompts-yet"></a>

### 아직 프롬프트가 없을 경우

프롬프트 목록이 비어 있다면 Transform 작업 영역에서 **샘플 프롬프트 불러오기**를 클릭하세요. 이와 동일한 기능은 내보내기/가져오기 항목에 있는 [**설정** > **Transform 프롬프트**](#transform-prompts)에서도 항상 이용 가능합니다. 두 방법 모두 기본 제공되는 예제를 추가하여 빠르게 시작할 수 있게 해줍니다.

<br/>

> ℹ️ **참고**<br/>
> 샘플 프롬프트는 영어로 제공됩니다. 불러온 후에는 각 프롬프트를 편집하고 **프롬프트 번역하기** 기능을 사용하여 사용자의 언어로 번역할 수 있습니다.

<br/>

<a id="create-a-prompt-quickly"></a>

### 빠르게 프롬프트 생성하기

프롬프트를 만드는 가장 빠른 방법은 다음과 같습니다.

1. **새 프롬프트**를 클릭합니다.
2. **프롬프트 생성**을 클릭합니다.
3. 프롬프트가 수행하길 원하는 내용을 설명하세요.
4. 모델을 선택합니다.
5. 앱이 초안을 작성하도록 합니다.
6. 초안을 검토한 후 **저장**을 클릭합니다.

![프롬프트 생성](../images/screenshots/ko/transform-generate.png)


<br/>

<a id="edit-a-prompt"></a>

### 프롬프트 편집하기

프롬프트를 만들거나 편집할 때 왼쪽에는 편집기 창이 나타나고, 오른쪽에는 테스트 영역이 나타납니다.

![프롬프트 편집 화면](../images/screenshots/ko/transform-prompt-edit.png)

주요 항목은 다음과 같습니다:

- **프롬프트 이름**: 프롬프트 목록에 표시되는 이름입니다.
- **프롬프트 지시사항(선택 사항)**: 프롬프트 실행 시 사용자에게 보여지는 간단한 안내 문구입니다.
- **모델 역할**: AI에게 부여되는 전체적인 역할이며, 예를 들어 '당신은 유용한 어시스턴트입니다.'와 같습니다.
- **모델 지시사항(한 줄에 하나씩)**: AI가 따라야 할 구체적인 규칙들입니다.
- **출력 설명**: 결과의 특성을 나타내는 짧은 단어로, '요약' 또는 '다시 작성' 등이 있습니다.
- **온도(0.0 → 1.0)**: 모델의 작동 방식을 결정하며, 아래 내용을 참고하세요.
- **타겟 언어 묻기**: 프롬프트 실행 시 대상 언어 선택 기능을 추가합니다.

**온도**(Temperature)라는 기술 용어가 처음이라면 다음과 같이 이해하시면 됩니다:

- **낮은** 온도는 더욱 일정하고 예측 가능한 결과를 생성합니다.

- **높은** 온도일수록 더 다양한 결과와 창의성이 나타납니다.

또한 다음을 사용할 수 있습니다:

- **`프롬프트 생성`** - 간단한 설명으로부터 새 초안 생성하기
- **`프롬프트 개선`** - 기존 프롬프트를 다듬고 개선하기
- **`프롬프트 번역`** - 프롬프트 항목 번역하기

<br/>

> ⚠️ **경고**<br/>
> **`Run으로 돌아가기`**를 클릭하기 전에 반드시 **`저장`**을 클릭하세요. 저장하지 않고 돌아가면 변경 내용은 모두 사라집니다.

<br/>

<a id="test-a-prompt-before-using-it"></a>

### 프롬프트 사용 전에 테스트하기

오른쪽의 테스트 패널을 사용하면 일상 업무에 적용하기 전에 샘플 텍스트로 프롬프트를 시험해 볼 수 있습니다.

이 기능은 다음 경우에 유용합니다:

- 새 프롬프트를 작성할 때
- 두 가지 프롬프트 버전을 비교할 때
- 톤, 길이 또는 출력 형식을 확인하고자 할 때

<br/>

> ℹ️ **참고**<br/>
> 저장된 프롬프트는 [**설정** > **변환 프롬프트**](#transform-prompts)에서 내보내기 및 가져오기를 할 수 있습니다.

<a id="general-settings"></a>

### 일반 설정

**일반 설정**을 사용하여 입력 동작, **기록**(History)에 실행 세부 정보를 저장할지 여부 및 외형을 제어할 수 있습니다.

**동작**

- **ENTER 동작**은 `Enter` 키를 누르면 작업을 실행할지 아니면 새 줄을 삽입할지를 결정합니다.
- **붙여넣기 시 자동 번역**은 텍스트를 붙여넣는 즉시 번역을 시작합니다.
- **결과를 클립보드로 자동 복사**는 성공한 결과를 자동으로 클립보드에 복사합니다.
- **실시간 번역(입력 중)**은 입력하는 도중에 번역을 수행합니다.
- **시간 초과(밀리초)** 는 실시간 번역을 위한 대기 시간을 설정합니다.

**기록**

- **실행 기록 유지**는 각 번역, 재작성, 변환 작업 시 사이드바의 [**기록**(History)](#history) 보기에서 **입력 및 출력 텍스트**를 저장할지 여부를 제어합니다. 이를 해제하면 확인을 요청하며, 확인 시 저장된 기록 텍스트는 데이터베이스에서 삭제됩니다.

- **기록 데이터 삭제**를 통해 나이별로 저장된 텍스트를 삭제할 수 있습니다 (예: 몇 달보다 오래된 데이터, 또는 **모든 데이터 삭제**(지우기)). 이는 **기록** 보기의 저장된 실행 텍스트에만 영향을 주며, 비용이나 사용량 총계는 **삭제하지 않습니다**. **비용** 데이터를 제거하거나 줄이려면 [**설정** > **비용 추적**](#cost-tracking)을 사용하세요.

**외형**

- **동작에 비용 정보 표시** — 작업당 비용(사용 가능한 경우)과 번역, 재작성, 변환 출력 패널의 총비용 표시 여부를 제어합니다.
- **비용 소수 자릿수** — 비용 소수점 이하 자릿수의 표시 방식을 변경합니다.
- **웹 전용:** **앱 주위에 여백 표시** — 인터페이스 주변에 여유 공간을 추가합니다.
- **글꼴** — 텍스트 패널의 글꼴을 변경합니다.
- **크기** — 글꼴 크기를 변경합니다.

**설정 백업**

- **백업에 사용량 데이터 포함** — 활성화 시 ZIP 파일에 실행 기록 및 API 호출 데이터도 함께 포함됩니다.

- **구성 백업** — `config.json`, `state.json`, 선택 사항인 암호화 키, 사용자, 환경 설정, 사용자 지정 프롬프트 및 사용 데이터(선택한 경우)를 포함하는 단일 ZIP 파일(`transrewrt-config-backup-YYYY-MM-DD_HHMMSS.zip`, 기본값으로 UTC 기준)을 생성합니다. 백업이 성공하면, 저장된 파일 이름이 확인 메시지에 표시됩니다.
- **백업에서 복원** — 먼저 **확인 대화상자**를 엽니다. 대화상자 안에서 백업 ZIP 파일을 선택합니다(**탐색** / 파일 선택기 또는 지원 시 드래그 앤 드롭), 그리고 다음 옵션을 검토합니다:
  - **사용 데이터 복원** — 백업 시 사용 데이터가 포함된 경우 해당 ZIP 파일에서 사용 기록을 가져옵니다. 설정과 프롬프트만 원할 경우 이 옵션을 비활성화하세요.
  - **복원 전 이전 사용 데이터 삭제** — 백업을 적용하기 전에 현재 설치된 프로그램의 기존 사용 기록을 제거합니다(선택 사항; 완전히 대체하고자 할 때 사용).

웹 버전이나 데스크톱 버전 중 어느 곳에서 생성한 백업이라도 서로 다른 버전에서 복원할 수 있습니다. 데스크톱 백업을 웹 버전에서 복원할 경우, 데이터는 관리자 사용자에게 복원됩니다.

<a id="models"></a>

### 모델

**설정** > **모델**에서 툴바에 표시할 모델을 선택할 수 있습니다.

![설정 모델 탭](../images/screenshots/ko/settings-models.png)

이 페이지에는 두 개의 목록이 있습니다:

- 왼쪽의 **사용 가능한 모델**
- 오른쪽의 **선택된 모델**

사용할 수 있는 주요 기능은 다음과 같습니다:

- **모델 검색...** – 이름으로 모델을 찾을 수 있음
- **공급자**(Provider) 칩 – 목록을 특정 엔진(OpenRouter, OpenAI, Ollama 등)으로 좁힐 수 있음
- **무료만** – 무료 모델만 표시
- **새로 고침** – 목록을 다시 불러옴
- **전체 확장** 및 **전체 축소** – 공급자별로 정렬할 때 유용

모델 ID는 공급자 접두사가 포함됩니다(예: `openrouter/…` 대신 `openai/…`). **OpenAI(OpenRouter)** 와 **OpenAI(직접)** 와 같은 배지는 트래픽이 어떻게 라우팅되는지 보여줍니다.

> ℹ️ **참고**<br/>

> **OpenRouter Body Builder**(`openrouter/bodybuilder`)는 일반 챗 모델이 아니라 라우터 모델입니다. 따라서 이 모델의 응답은 완성된 텍스트가 아니라 OpenRouter API 요청 본문(예: `model` 및 `messages`를 포함하는 `requests` 배열)을 설명하는 JSON 형식입니다. **번역**, **다시 작성** 또는 **변환** 작업에 이 모델을 사용하면 출력 패널에 최종 텍스트 대신 해당 JSON이 표시됩니다. 이러한 작업에는 일반 텍스트 모델을 선택하세요. 자세한 정보는 OpenRouter의 [Body Builder 모델 페이지](https://openrouter.ai/openrouter/bodybuilder)를 참조하세요.

작업:

 - 모델을 추가하려면 **추가** 버튼이나 목록 내 아무 곳이나 클릭하세요.

 - 모델을 제거하려면 **선택된 모델** 목록에서 해당 옆의 **X**를 클릭하거나, 사용 가능한 모델 목록에서 항목의 **선택됨** 부분 옆의 **X**를 클릭하세요.

 - 목록을 모두 해제하려면 **모두 해제**를 클릭하세요. 이때 필수인 무료 모델은 목록에 그대로 유지됩니다.

<br/>

> ℹ️ **참고**<br/>

> 즉시 OpenRouter에 크레딧을 추가하고 싶지 않은 경우, 먼저 **무료 전용(Free Only)** 옵션을 활성화하고 무료 모델을 선택하세요(신용카드 필요 없음). 또한 Ollama를 사용하여 로컬에서 모델을 실행할 수 있으며, 이 경우 API 키가 필요하지 않습니다.

<a id="cost-tracking"></a>

### 비용 추적

**설정** > **비용 추적**에서 비용 정보를 관리할 수 있습니다.

- **총 비용**은 누적된 총합을 표시합니다.
- **값 복사**는 총액을 클립보드에 복사합니다.
- **비용 초기화**는 저장된 총액을 0으로 재설정합니다.
- **API 키 사용량과 동기화**는 저장된 총액을 OpenRouter 계정에서 보고한 사용량과 일치하도록 설정합니다. (OpenRouter 전용)
- **API 키 사용량**은 사용 가능한 경우 OpenRouter의 사용 상세 정보를 표시합니다.
- **비용 데이터 삭제**는 모든 데이터를 삭제하거나 선택한 날짜보다 오래된 항목만 제거할 수 있습니다.

**비용 추적 정보:** OpenRouter 모델을 사용할 경우 앱은 OpenRouter에서 제공하는 비용 정보를 기반으로 실제 사용량과 지출 내역을 표시합니다. 다른 제공자들의 경우, OpenRouter에서 공개한 요금 기준으로 비용을 추정하며, 요금 정보가 없을 경우 추정 비용이 0으로 표시될 수 있습니다.

<br/>

> ℹ️ **참고**<br/>
> 모든 비용 수치는 참고용으로만 제공되며, 공식 청구서가 아닙니다.

<br/>

> ⚠️ **경고**<br/>

> 데이터 삭제는 취소할 수 없습니다. 삭제하기 전에 반드시 데이터를 백업하거나 [**기록**](#history) 또는 [**대시보드** > **모든 호출**](#dashboard-tabs)을 통해 내보내기하세요. 그렇지 않으면 데이터가 영구적으로 삭제됩니다.  
> 각 API 호출 항목과 관련된 모든 입력/출력 기록도 함께 삭제됩니다.

<a id="api-config"></a>

### API 설정

지원되는 제공자는 다음과 같습니다: OpenRouter, OpenAI, Anthropic, Google Gemini, DeepSeek, Groq, Mistral, xAI, Cerebras, 그리고 **Ollama** (기본 URL을 통한 로컬 모델). 사용하는 제공자만 설정하면 됩니다.

**웹 애플리케이션: 관리자만 해당**

API 키는 시스템 또는 Docker 환경 변수를 통해 설정되며, 웹 UI에 입력하지 않습니다. 이 페이지에서는 어떤 제공자에게 API 키가 설정되어 있는지 확인할 수 있으며, 각각의 제공자 아래에 있는 **`테스트`** 버튼을 클릭하여 테스트할 수 있습니다.

<br/>

> ℹ️ **참고**<br/>
> API 키를 변경하려면 시스템 또는 Docker 설정에서 환경 변수를 업데이트하고 서버 또는 컨테이너를 재시작해야 합니다.

> ℹ️ **참고**<br/>

> **구성 백업**( [**일반 설정** → 구성 백업](#general-settings) 참조)은 ZIP 파일 내 `config.json`에 **해결된(resolved)** 제공자 키를 포함할 수 있습니다. 해당 ZIP을 복원하더라도 서버의 영구 구성 파일로는 이러한 키들이 복사되지 않습니다. 라이브 키는 이곳에 설명된 대로 여전히 환경 변수와 기존 파일 상태에서 가져옵니다.

<br/>

**데스크탑 애플리케이션**

사용하는 각 제공자에 대한 API 키는 **API 구성**을 통해 저장할 수 있습니다. Ollama의 경우 API 키 대신 **기본 URL**을 입력하세요.

<br/>

> 💡 **팁** <br/>
> API 키 사용을 원하지 않거나 요금을 지불하고 싶지 않다면, [Ollama 다운로드](https://ollama.com)를 통해 여러분의 기기에서 무료로 모델(예: `translategemma:4b`)을 실행할 수 있습니다. 또는 무료 OpenRouter 계정을 생성해(신용카드 불필요) 무료 모델을 사용하거나, Cerebras, Google, Groq, Mistral AI 등에서 무료 API 키를 발급받을 수도 있습니다.

<br/>

- 필요한 제공자만 추가하세요. **설정** > **모델**에서 각 모델 ID는 제공자 이름으로 시작합니다(예: `openrouter/openrouter/free`, `openai/gpt-4o`, `ollama/llama3`).

API 키를 추가하려면 텍스트 필드에 값을 입력하고 **`저장`** 을 클릭하세요. 기존 키를 교체하려면 **`편집`** 을 클릭하세요. 키가 제대로 작동하는지 확인하려면 **`테스트`** 를 클릭하세요. Ollama의 기본 URL의 경우, 항상 **`테스트`** 를 클릭하여 연결 상태를 확인해야 합니다.

<br/>

> ℹ️ **참고**<br/>
> API 키의 현재 값을 확인할 수 없습니다. **`편집`** 버튼을 사용하여 키를 교체하는 것만 가능합니다.
> API 키는 구성 파일에 암호화되어 저장됩니다.

<a id="common-issues"></a>

## 일반적인 문제

예상대로 동작하지 않는 경우, 먼저 다음 사항들을 확인해 보세요.

<br/>

<a id="the-app-will-not-translate-rewrite-or-transform-text"></a>

### 앱이 텍스트를 번역, 다시 작성 또는 변환하지 않습니다

다음 사항을 확인하세요:

- 툴바에서 모델을 선택했는지 여부
- [**설정** > **모델**](#models)에 최소한 하나의 모델이 목록에 있는지 여부
- API 설정이 정상적으로 작동 중인지 여부

데스크탑 앱을 사용하는 경우:

1. [**설정** > **API 구성**](#api-config)을 엽니다.
2. 최소한 하나의 API 키가 저장되어 있는지 확인합니다.
3. 제공업체 옆의 **테스트** 버튼을 클릭하여 키가 올바르게 작동하는지 확인합니다.

<br/>

<a id="the-model-list-is-empty"></a>

### 모델 목록이 비어 있습니다

[**설정** > **모델**](#models)을 열고 **새로고침**을 클릭하세요.

필요한 경우 다음을 수행하세요:

- 모델을 검색하세요
- **무료 전용**을 켜세요
- 하나 이상의 모델을 **선택한 모델**에 추가하세요

<br/>

<a id="the-result-is-too-slow-or-too-expensive"></a>

### 결과가 너무 느리거나 비용이 너무 높은 경우

다음 방법 중 하나 이상을 시도해 보세요:

- 다른 모델을 선택하세요
- 입력을 더 짧게 하세요
- [**설정** > **일반 설정**](#general-settings)에서 **입력 중 실시간 번역** 기능을 끄세요
- 간단한 작업에는 무료 모델을 사용하세요(자세한 내용은 [모델](#models) 참조)

<br/>

### 인터페이스가 잘못된 언어로 표시됨

[도구 모음](#toolbar)에서 지구본 아이콘을 클릭하고 원하는 **인터페이스 언어**를 선택하세요.

<br/>

<a id="the-text-is-too-small-or-hard-to-read"></a>

### 텍스트가 너무 작거나 읽기 어렵습니다

[**설정** > **일반 설정**](#general-settings)을 열고 다음을 변경하세요:

- **글꼴**
- **크기**

<br/>

<a id="dashboard-charts-are-empty"></a>

### 대시보드 차트가 비어 있습니다

다음과 같은 경우 정상적인 현상입니다.

- **무료 모델**만 사용 중이고 **비용** 수치를 확인하고 있는 경우(비용이 0일 수 있음); **요약(Summary)** 탭의 **사용량**(콜 수) 차트도 선택한 기간의 데이터가 필요합니다.
- 선택한 **시간 필터**가 API 호출 기간을 포함하지 않는 경우 — 제대로 나타나는지 확인하려면 **전체(All)** 옵션을 사용해 보세요.

**전체(All)** 를 선택한 후에도 차트가 여전히 비어 있다면, [**기록(History)**](#history) 또는 **모든 호출(All Calls)** 탭에 호출 내역이 표시되는지 확인하십시오.

<br/>

<a id="cost-shows-not-available-or-seems-wrong"></a>

### 비용이 "사용할 수 없음"으로 표시되거나 잘못된 경우

**OpenRouter**를 통해 모델을 사용할 때, 앱은 OpenRouter에서 보고된 실제 지출 금액을 표시합니다.

**기타 제공업체**(OpenAI 직접, Anthropic 직접 등)의 경우, 비용은 OpenRouter에서 공개한 가격 정보를 기반으로 추정됩니다. 모델에 해당하는 가격 정보를 찾을 수 없는 경우, 비용은 **사용할 수 없음**으로 표시되며 누적 비용 합계에 포함되지 않습니다.

<br/>

<a id="total-cost-does-not-match-my-provider-bill"></a>

### 총 비용이 제공업체 청구서와 일치하지 않음

앱 내 모든 비용 정보는 **참고용 예상치**이며, 공식 청구서와는 다를 수 있습니다.

실제 OpenRouter 비용과 총액을 더 가깝게 맞추려면, [**설정** > **비용 추적**](#cost-tracking)을 열고 **API 키 사용량과 동기화**를 클릭하세요.

<br/>

<a id="the-history-page-is-missing-from-the-sidebar"></a>

### 사이드바에서 역사 페이지가 누락됨

**실행 기록 유지**가 꺼져 있을 수 있습니다. [**설정** > **일반 설정**](#general-settings)으로 이동하여 이 기능을 활성화하세요. 이 기능을 켜도 이전에 삭제된 기록 데이터는 복원되지 않음을 참고하세요.

<br/>

<a id="web-app-session-expired"></a>

### 웹 앱: 로그인 페이지로 예기치 않게 리디렉션됨

세션이 만료되었을 수 있습니다. 다시 로그인하세요. 이 현상이 자주 발생한다면, 서버 설정에서 세션 유지 시간을 확인하십시오.

<br/>

<a id="web-admin-forgot-or-lost-a-password"></a>

### 웹 관리자: 비밀번호 분실 또는 잊어버린 경우

이 내용은 데스크탑(Electron) 앱이 아닌 **자체 호스팅 웹 앱**(Docker)에 적용됩니다.

- 다른 관리자가 여전히 로그인할 수 있는 경우, [**설정** > **사용자**](#users)를 열고 해당 계정을 선택하여 **새 비밀번호**를 설정할 수 있습니다.
- 로그인은 불가능하지만 서버 또는 컨테이너에 **셸(shel) 접근 권한**이 있는 경우, 이미지와 함께 제공되는 도구를 사용하여 비밀번호를 재설정할 수 있습니다(기본 이름을 변경한 경우 `transrewt`를 적절한 이름으로 바꾸세요. 비밀번호에 공백이나 특수문자가 포함된 경우 따옴표로 감싸야 합니다.).

```bash
docker exec transrewrt reset-web-password '<username>' '<new-password>'
```

기타 계정을 생성한 적이 없다면 기본 관리자 사용자 이름은 `admin`입니다. 인수를 하나만 입력할 경우, `admin` 계정의 새 비밀번호로 간주됩니다.

Docker 대신 **소스 코드를 체크아웃**하여 실행 중인 경우 다음을 사용하세요:

```bash
pnpm run reset-web-password -- <username> <new-password>

스크립트는 SQLite 데이터베이스의 사용자 정보를 업데이트하며, 필요 시 `admin` 사용자를 생성할 수도 있습니다. 재설정 후에는 새 비밀번호로 로그인하십시오.

<br/>

<a id="dashboard-shows-no-data-for-other-users"></a>

### 대시보드에 다른 사용자의 데이터가 표시되지 않음(웹)

**관리자**만 **사용자** 필터를 통해 모든 사용자의 데이터를 볼 수 있습니다. 일반 사용자는 설계상 자신만의 활동 데이터만 확인할 수 있습니다.

<br/>

<a id="i-changed-a-prompt-and-lost-the-edits"></a>

### 프롬프트를 변경했는데 편집 내용이 사라졌습니다

프롬프트를 편집할 때는 항상 **실행으로 돌아가기**를 클릭하기 전에 **저장**을 꼭 클릭해야 합니다.

## 빠른 팁

- [**번역**(Translate)](#translate) 기능부터 시작해서 [**재작성**(Rewrite)](#rewrite) 또는 [**변환**(Transform)](#transform) 기능을 사용하기 전에 설정이 제대로 작동하는지 확인하세요.
- 일상적인 문장 개선에는 [**재작성**(Rewrite)](#rewrite)을 사용하세요.
- 특정 작업을 위한 반복 가능한 워크플로우가 필요한 경우 [**변환**(Transform)](#transform)을 사용하세요.
- 사용량 및 비용을 확인하고 싶다면 [**대시보드**(Dashboard)](#dashboard)를 사용하세요.
- 이전 작업과 그 전체 입력/출력 내용을 검토하려면 [**기록**(History)](#history)을 사용하세요.
- 안전하게 보관하고자 하는 프롬프트 라이브러리를 제작하거나 다른 사람들과 공유하고자 한다면 정기적으로 프롬프트를 내보내세요 (자세한 내용은 [**변환 프롬프트**(Transform Prompts)](#transform-prompts) 참고).
