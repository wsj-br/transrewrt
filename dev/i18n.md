## Overview

- **Default language:** UK English (`en-GB`). The app uses a **key-as-default** approach: the translation key is the English string itself, so there is no separate `en-GB.json` file.
- **Locale configuration:** In **Electron** mode the UI language is stored in config as `ui_locale`. In **Web/Docker** mode it can be stored in `localStorage` (e.g. on the login page) or provided by the server; the app uses `loadLocale()` and `i18n.changeLanguage()` to switch.
- **Strings:** All user-visible strings are extracted from source into `src/renderer/locales/strings.json`. Translations are produced by the **`ai-i18n-tools`** CLI (OpenRouter); per-locale JSON files (e.g. `de.json`, `pt-BR.json`) are generated from that catalog.
- **Project config:** Root [`ai-i18n-tools.config.json`](../ai-i18n-tools.config.json) drives extract, UI translation, and documentation translation. **`targetLocales`** is an array of BCP-47 codes; **`ui-languages.json`** is generated with `pnpm exec ai-i18n-tools generate-ui-languages` (includes `direction` for each row).

## Configuration and runtime

- **Initialization:** [`src/renderer/i18n.js`](../src/renderer/i18n.js) uses `defaultI18nInitOptions`, `wrapI18nWithKeyTrim`, `makeLoadLocale`, and `applyDirection` from **`ai-i18n-tools/runtime`**. It exports **`SOURCE_LOCALE`** (`'en-GB'`), which must match **`sourceLocale`** in `ai-i18n-tools.config.json`.
- **Loading a locale:** For any language other than `SOURCE_LOCALE`, the app dynamically imports `locales/<code>.json` and registers the bundle. **`loadLocale(lang)`** is created with `makeLoadLocale`.
- **When the language is applied:** In Electron, after config is loaded, `ui_locale` is read and `loadLocale(uiLocale)` then `i18n.changeLanguage(uiLocale)` are called. In Web, the login page may restore language from `localStorage`. When the user changes the language, call `await loadLocale(code)` then `i18n.changeLanguage(code)` and persist `ui_locale` or `localStorage` as appropriate.
- **Language labels:** Use `getUILanguageLabel` / `getUILanguageLabelNative` from **`ai-i18n-tools/runtime`** (imported from the package, not local utils).

## Using i18n in source code

### Basic usage: `t()`

Use the `t()` function from `useTranslation()` with a **literal string** so the extract command can find it:

```js
import { useTranslation } from "react-i18next";

function MyComponent() {
  const { t } = useTranslation();
  return (
    <>
      <button>{t("Save")}</button>
      <span>{t("Loading…")}</span>
    </>
  );
}
```

Only these forms are extracted: `t("...")`, `t('...')`, `` t(`...`) ``, `i18n.t("...")`, etc. Do **not** pass variables as the key.

### Interpolation (placeholders)

Use i18next’s **second argument** for `{{name}}`-style placeholders. The runtime helper **`wrapI18nWithKeyTrim`** applies interpolation even when the source locale returns the raw key:

```js
t("Hello {{name}}", { name: userName });
t('Delete model "{{model}}"?', { model: modelName });
```

For non-translated strings, [`interpolateTemplate`](../src/renderer/utils/misc/formatUtils.js) can still replace `{{key}}` in plain strings; prefer `t('…', vars)` for UI copy.

### Dropdowns and option lists

Call `t()` at **definition** time, not with a dynamic key:

```js
const options = useMemo(
  () => [
    { label: t("Option A"), value: "a" },
    { label: t("Option B"), value: "b" },
  ],
  [t]
);
```

### Getting the current locale

- **For UI text:** use `t()`; the current language is applied by i18next.
- **For formatting numbers/dates:** use `useFormatLocale()` (`src/renderer/hooks/useFormatLocale.js`).
- **Direct access:** `i18n.language`; import `i18n` or `SOURCE_LOCALE` from `src/renderer/i18n.js` as needed.

### Changing the language

Call `await loadLocale(code)` then `i18n.changeLanguage(code)`. Persist in config (`ui_locale`) or `localStorage` for Web.

## Translation workflow

1. **Add or change UI strings** in code with `t("…")` literals.
2. **Extract:** `pnpm run i18n:extract` — updates `src/renderer/locales/strings.json`.
3. **Translate UI:** `pnpm run i18n:translate:ui` (or `pnpm run i18n:translate` for UI + SVG + docs pipeline). Requires `OPENROUTER_API_KEY` for new translations.
4. **Docs:** `pnpm run i18n:translate:docs` translates `README.md` / `USER-GUIDE.md` per `documentations` in `ai-i18n-tools.config.json`. Cache: **`cacheDir`** (default `.translation-cache`).
5. **Combined:** `pnpm run i18n:sync` runs extract + UI translation + optional SVG + docs per `features` in config.

**Regenerate manifest:** After changing `targetLocales`, run `pnpm exec ai-i18n-tools generate-ui-languages` to refresh `ui-languages.json` (review labels if you had custom `label`/`englishName` values).

## pnpm scripts


| Script | Description |
|--------|-------------|
| **i18n:extract** | `ai-i18n-tools extract` — refresh `strings.json`. |
| **i18n:sync** | `ai-i18n-tools sync` — extract + translate UI (+ SVG/docs per config). |
| **i18n:translate** | `translate-ui` then `translate-svg` then `translate-docs`. |
| **i18n:translate:ui** | UI strings only. |
| **i18n:translate:svg** | Standalone SVG (if enabled in config). |
| **i18n:translate:docs** | Markdown docs per `documentations`. |
| **i18n:status** | Markdown translation status. |
| **i18n:editor** | Local cache/strings editor. |
| **i18n:cleanup** | `ai-i18n-tools cleanup` — sync force-update then cache cleanup. |

See **`pnpm exec ai-i18n-tools --help`** and **`pnpm exec ai-i18n-tools translate-ui --help`** for flags (`--dry-run`, `--locale`, `--force`, etc.).

| `glossary-user.csv` | Optional user glossary. |
| `.translation-cache/` | SQLite cache for documentation translation (not the old `translated-docs/.cache` schema). |

## RTL (right-to-left) languages

Direction is handled by **`applyDirection`** from `ai-i18n-tools/runtime` (wired to `languageChanged`). Use **`getTextDirection`** from `ai-i18n-tools/runtime` where components need RTL-aware layout. For arrows in strings, use **`flipUiArrowsForRtl`** from [`formatUtils.js`](../src/renderer/utils/misc/formatUtils.js) when needed.
